## 2. 設計理由與限制

- 寫入工具不進唯讀白名單，延續 010「限制做在 server 端」原則（唯讀 wrapper 在 transport 層拒絕寫入工具）。（SRC-004）
- 工具不收網址：避免被對話內容或第三方文字誘導去抓任意網址（提示注入、SSRF 類風險）；只能對設定檔內已啟用作者的 feed 發請求。（SRC-002「不接受網址」）
- 最小間隔守衛：避免被誘導或誤用而密集請求、觸發站方封鎖；預設 30 分鐘、為可隨時調整的設定（不寫死），排程與即時取得都計入。（SRC-002；Q-102）
- parity 測試僅對該工具名稱例外，其餘工具仍須逐字相同；該例外須有專屬測試。（SRC-002）

## 3. 授權與執行確認

- PO 須在當下對話親自確認的範圍（FR-014，Q-101 已答）：**登入、鑰匙圈、消耗訂閱用量**，以及**安裝排程**。011 不登入、不碰鑰匙圈、排程不消耗用量，故 RSS 輪詢（排程與即時取得）不另逐次確認。
- 手動轉寫（FR-010）會消耗訂閱用量，須 PO 當下對話親自確認。
- 不由別的對話代為同意。（SRC-001 010補充）
- 給 PO 的操作指令一律 zsh 相容。（SRC-001）

## 4. 安全與隱私要求

| 項目 | 要求 |
|------|------|
| 不登入、不用 cookie | 任何階段皆不使用 PO 的 Substack 登入資訊；不接觸鑰匙圈（公開 RSS 無密碼，SRC-004） |
| 內容範圍 | 只存公開可見內容（免費全文＋付費預覽），不繞付費牆 |
| 日誌／錯誤訊息 | 不含標題、全文、帳密、cookie、token；通知可含作者＋標題（Q-009） |
| 外洩掃描 | 沿用 010 的外洩掃描機制並新增 011 對應測試 |
| 對外請求識別 | 通用 User-Agent，不含 PO email／個資 |
| 子行程環境 | 環境白名單須含 USER 與 LOGNAME |
| 資料去向 | 僅 PO 個人本機參考，不轉發、不公開、不批量備份他人作品；資料不得出現在任何對外服務或公開位置 |
| 路徑比對 | macOS `/var`→`/private/var`，路徑一律以 realpath 比對 |
| 新資料目錄防呆 | 沿用 010 的資料目錄防呆，測試用獨立資料目錄 |

## 4b. ToS 風險承擔與使用約束（Q-107，PO 原話「確認。」）

- PO 明確承擔 Substack ToS 灰色地帶風險（研究為二手轉述、非法律意見，不構成合法性保證）。
- 條件（產品約束）：僅供 PO 本人本機使用；不轉發；不公開；不批量備份他人作品；資料不得出現在任何對外服務或公開位置（含公開網址、公開分支、對外分享）；僅公開 RSS 低頻取得、不登入、不繞付費牆。
- 規格階段須把此約束轉成可驗證項（例如：連接器以外無對外暴露、備份範圍只含 PO 本機自用資料的決策見 Q-111，且不得變成批量備份他人作品的對外副本）。

## 5. 稽核期望

- 日誌保留每次執行的時間、作者代號、狀態碼、計數（無標題）。
- 守門測試與無洩漏測試輸出作為驗收證據；由全新 agent 獨立驗收（SRC-001 流程）。

## 6. 新增寫入工具與 010「文章通道唯讀」守門的關係

- 010 既有守門：文章通道（`article_tools`）以**唯讀**方式開庫、查詢不寫 `alphavibe.db`／`us_stocks.db`，並有對應測試。（SRC-004）
- 011 新增的即時取得是**寫入工具**，只寫 `substack.db`（與圖片目錄），與文章查詢（唯讀）是不同工具、不同開庫方式。
- 要求（FR-027）：
  1. 010 既有唯讀守門測試全數維持通過，不得為了新工具放寬（唯一放寬為 parity 測試對新工具名稱的例外，見第 2 節）。
  2. **另行證明**守門未被破壞：寫入工具的程式路徑與唯讀查詢路徑分離；`search_articles`／`get_article` 對 `substack.db` 仍以唯讀開啟；寫入工具不會寫 `alphavibe.db`／`us_stocks.db`／`articles.db`。證明方式（測試或前後比對）由規格階段設計。
  3. 唯讀白名單（數量不變）不含該寫入工具，由測試證明。
- 風險：MCP 工具呼叫有逾時；即時取得含同步下載圖片可能超時。產品要求（FR-028）：在逾時內必有回應，能完成回完整結果，來不及則回已存篇數與進度、剩餘圖片交排程補下載。具體機制與逾時上限待規格階段（Q-118）。

## 7. 來源可信度標示（FR-029）

- 引用 Substack 作者意見時，須標明來源（作者／出版名稱）與「僅預覽」（若適用），讓 PO 能分辨：這是第三方作者的意見，不是 PO 自己的研究或定錨筆記；且內容是否完整。
- 搜尋與讀取結果須帶足以支援此標示的資訊（來源名稱、完整度）；是否另加其他可信度資訊（如發布日期）留待規格階段。（SRC-001 Components 3）
