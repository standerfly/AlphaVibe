## 1. 文章核心框架（摘要）

主張：散戶缺的不是資訊，是**一套每次都跑同一遍的研究流程**。具體給出：

- **業務理解三句話**：賣什麼／誰付錢／護城河為何（護城河須來自技術、
  品牌、規模、網路效應、專利等客觀優勢，非「產品很好」）
- **產業五問**：TAM規模／產業週期／定價權／競爭格局／價值鏈瓶頸
- **財務六面向**：營收品質（拆解成長來源）／毛利與營業槓桿／現金流／
  資產負債表（尤其成長股燒錢速度）／法說會Q&A／資訊來源分級（官方
  資料為主，競爭對手財報交叉驗證）
- **估值**：不做單一目標價，改用熊/中/牛情境＋機率加權；核心是
  **「預期差」**——市場已經反映了多少預期，不是公司好不好
- **投資論點破裂條件**：買進前就先寫好「什麼情況代表我錯了」
- **12問一頁研究表**：填不完先不買
- **方法論**：深度優先於廣度（選一產業深挖，複利效應）；新聞用於
  「更新」論點，不用於「建立」論點

## 2. 對照 AlphaVibe 現有設計

### 2.1 已對齊、算是驗證方向對的部分

| 文章概念 | AlphaVibe 對應 |
|---|---|
| 投資論點破裂條件 | FR-052 策略專屬層「假說失敗長什麼樣子」、原 `framework_thesis_invalidation_exit` |
| 新聞只更新論點不建立論點 | 模組A資訊蒐集→Layer 2立場更新，走確認制，非自動觸發買賣 |
| 不追單一目標價、質化為主 | FR-021 已實測 `entry_condition` 目標價0%使用，改走質化判斷——見下方2.3 |
| 深度優先於廣度 | FR-041 投資主題標籤／FR-054 集中度上限，精神一致 |

### 2.2 有缺口、成本低、值得評估補上的部分

1. **「預期差」完全沒被覆蓋**——模組C篩選（PEG／回檔幅度／營收年增率）
   與 FR-051 通用檢視都是問「數字好不好」，沒有問「市場是否已經定價」。
   查證 `review_engine.py`：FR-051 五項檢查中「財報兌現度／利多出盡／
   預期獲利能否持續上修」三項本來就是 `manual_notes`（質化、對話層
   判斷，非程式運算），只有「成長趨緩／下檔風險」兩項是自動計算
   （`_growth_deceleration`／`_downside_risk`）。加一項「預期差」質化
   提問，等於加一條 prompt，不是加開發工作量。
2. **業務理解／護城河／產業結構完全沒有進到流程**——模組C是純財務數字
   篩選，篩出後直接進模組D財務向檢查，中間沒有「這家公司靠什麼賺錢、
   護城河是什麼」這一關。符合現有分工（量化粗篩交程式、質化判斷交
   PO+Claude對話），但目前沒有一份引導這段對話的清單。
3. **現金流／資產負債表健康度沒有獨立檢查項**——FR-051 五項裡沒有
   對應「現金夠不夠燒過景氣下行」這類檢查，對成長股/小型股尤其重要。

### 2.3 地雷：不建議照抄的部分

文章推薦「熊/中/牛三情境估值＋機率加權」，但 AlphaVibe **已經用真實
資料驗證過這條路線在實際使用模式下行不通**：product-spec.md FR-021
明確記錄 `entry_condition`／`time_horizon`／目標價區間欄位在33筆立場
裡 **0%使用**，最後拿掉「量化目標價」的強制要求，改成質化的信心程度
＋風險因子判斷，FR-054 部位控制建議承接了原本期待「目標價區間」該做
的事。

結論：「寫成結構化數字（表格/欄位）」跟「PO實際會不會維護」是兩件
事——已經吃過這個虧。若要借用「情境分析」的精神，建議走**質化敘事版**
（熊情境要成立需要什麼、牛情境要成立需要什麼），存進既有 `reason`／
`risk_factor` 自由文字欄位，不建議重開結構化「熊估值/中估值/牛估值」
欄位，避免重演 entry_condition 的下場。
