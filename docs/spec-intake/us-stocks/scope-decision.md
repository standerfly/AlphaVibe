# Scope Decision: Us Stocks

**Feature Slug:** us-stocks
**Last Updated:** 2026-09-04

## MVP In Scope

- STND 導覽新增獨立「美股」分頁（不併入「投資」或「資產」）（FR-01）
- 美股 landing 頁：追蹤清單，每檔顯示現價/漲跌/立場/觸發狀態（FR-07）
- 個股詳情頁：股價走勢圖＋買賣點位標記，視覺風格比照台股 `StockComboChart`，資料源獨立（FR-03）
- 投資立場／研究筆記功能：討論結果結構化存入（買/賣/觀望＋情境區間＋論點），完整研究筆記可在個股詳情頁原生查看，不壓縮內容（FR-04, FR-05）
- 關注條件清單：可設定門檻、比對最新資料、標示觸發狀態（FR-06）——實際通知方式待 Q-002 決定
- 交易紀錄匯入（截圖→辨識→人工核對→寫入，不論辨識完整度一律經人工核對才落庫，Q-003）（FR-02）
- 視覺規範：紅漲綠跌/紅買綠賣沿用台股既有慣例，全站一致（FR-08）
- 美股資料表與 KB 均獨立於台股既有系統（不含「怎麼實作獨立KB」的技術方案，見 Q-005）
- 報價/基本面資料改採免費API多來源（主要FMP，備援候選Alpha Vantage/yfinance），每日一次背景排程自動刷新（比照market_scan.py先例）；額度用盡時未刷新股票顯示「未更新（無額度）」，保留上次成功資料（Q-001第三輪決定，推翻第二輪的按需查詢）
- 關注條件觸發時透過既有 Telegram 閘道（`function/stnd-gateway-web`）推播通知（Q-002，原列 Deferred，現移入 MVP）
- 交易截圖不永久保留，僅在辨識/核對流程中暫存，確認或取消後即刪除（Q-004）

## Out Of Scope

- 交易紀錄的 CSV/報表匯入（僅截圖，MVP 不做；CSV 若未來需要視為獨立擴充）
- 付費報價API方案（FMP／Alpha Vantage的付費升級層、Polygon.io等）——MVP僅用免費層
- 每日一次以外的排程頻率（例如每小時刷新）——Q-001第三輪只定案「每日一次」，理由是250次/日的免費額度撐得住每天一次，更高頻率有超額風險
- 多使用者/多角色權限設計（本系統為使用者個人系統）
- 美股與台股資料的任何跨市場彙總計算（例如合併損益、合併資產總覽）——與「獨立不混淆」的核心決策直接衝突，明確排除
- 截圖原始檔的永久保存（Q-004 已定案不保留）

## Deferred Or Later

- 美股獨立 KB 的具體技術實作方案——待 speckit-plan 階段決定（Q-005）
- 「結構化內容→STND頁面元件」研究筆記渲染的技術做法——待 speckit-plan 階段決定（Q-006）
- 備援報價來源的最終選定（Alpha Vantage vs yfinance）與主/備切換邏輯——待 speckit-plan 階段決定
- 若免費API額度未來仍不敷使用，是否升級付費方案——需使用者重新提出才會評估，非待辦

## Split Feature Decisions

| Spec Feature Slug | Scope Summary | Dependencies | Handoff Order | Status |
|-------------------|---------------|--------------|---------------|--------|
| us-stocks | 美股獨立投資系統 MVP 全部功能（分頁、交易匯入、股價圖、研究筆記、關注條件監控、推播）合併為單一 Spec Kit input package，不拆分 | 無（單包） | 1 | Draft |

**不拆分的理由**：product-spec 定案後重新檢視，原先考慮的四個候選拆分方向
（資料層/UI/研究筆記渲染/關注條件監控）彼此耦合度高——例如關注條件監控
（FR-06）依賴股價圖的同一組報價資料（FR-03），研究筆記渲染（FR-05）與
投資立場（FR-04）是同一張卡片的一體兩面。這整個 MVP 本來就是要合併成一個
「美股」分頁一次上線，拆成多包會增加不必要的跨包協調成本，且 repo 內其他
既有 feature（`alphavibe`、`entry-exit-timing-analysis`）在 pre-spec 階段
也都未曾拆成多個 speckit-input package，維持單包與既有慣例一致。
