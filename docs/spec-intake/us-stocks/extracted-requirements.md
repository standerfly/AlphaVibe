# Extracted Requirements: Us Stocks

**Feature Slug:** us-stocks
**Last Updated:** 2026-09-04

## Candidate Functional Requirements

- FR-01 STND 導覽新增獨立的「美股」分頁，不併入既有「投資」（台股）或「資產」分頁（SRC-001 §2）
- FR-02 美股交易紀錄以截圖形式匯入：上傳券商 App/網頁截圖 → 系統辨識 → 人工核對 → 確認寫入（SRC-001 §4, §6）
- FR-03 個股詳情頁提供股價走勢圖，疊加買賣點位標記，視覺呈現比照台股既有 `StockComboChart` 元件風格（顏色/圖例/線稿），但資料來源與資料表完全獨立於台股（SRC-001 §4, §5, §7）
- FR-04 支援「研究筆記／投資立場」記錄：使用者與 Claude 討論個股後，產出結構化立場（買/賣/觀望＋目標價格帶／情境區間＋論點摘要），並保留完整研究筆記內容（SRC-001 §3, §5, §6, SRC-003示範內容）
- FR-05 個股詳情頁可查看完整研究筆記內容，在 STND 內以既有卡片/字體/配色系統原生渲染，不因版面一致而砍減內容（SRC-001 §8–§11，使用者於§11明確否決壓縮版）
- FR-06 支援「關注條件」清單：可設定門檻（例：股價/毛利率/NRR等指標），系統取得最新資料後比對是否碰觸條件，碰觸時在美股分頁與個股詳情頁標示警示狀態（SRC-001 §4, §5）
- FR-07 美股分頁 landing 呈現追蹤中清單，每檔顯示現價/漲跌、立場、觸發狀態一覽（SRC-002 Main.dc.html 畫面內容）
- FR-08 漲跌與買賣點位視覺色彩沿用台股既有慣例（紅=漲/買進，綠=跌/賣出），全站一致，不採國際慣例（SRC-001 §7，使用者明確決定）

## Candidate Actors And User Goals

- Stander（唯一使用者，同時是 PO/TPM/系統唯一操作者）：追蹤自己的美股持股與觀察清單、記錄研究討論結果、被動察覺關注條件是否已觸發、回顧交易紀錄與股價走勢的對照關係

## Candidate Success Criteria

- 使用者能在美股分頁一眼看出「哪些持股/關注股觸發了警示」，不用逐檔比對（對應 FR-06, FR-07）
- 使用者能把跟 Claude 討論出的投資立場保留在系統裡，之後回顧時不需要重新翻找對話記錄（對應 FR-04, FR-05）
- 使用者提供交易截圖後，系統能正確辨識並在人工核對後寫入紀錄，不需要逐筆手動輸入（對應 FR-02）
- 美股資料與台股資料在分頁、資料表、KB 三層都不互相汙染或混淆（對應 SRC-001 §5, §9 的獨立性決定）

## Candidate Constraints And Assumptions

- 美股相關資料表（交易紀錄、立場、關注條件、報價歷史）不得與既有台股資料表（`trade_ledger`、`stance` 等）共用（SRC-001 §5）
- 美股查詢用 KB 也必須與既有台股 KB（`mcp__alphavibe-kb__*`）完全獨立，不共用同一個資料庫（SRC-001 §9）
- 幣別一律 USD，不與台股 TWD 混合計算加總
- 這是單一使用者的個人系統，不需要多使用者/多角色權限設計
- 美股報價資料源尚未決定（見待釐清問題）——功能範圍與可靠度取決於此決定
- 假設：交易匯入的「截圖」來源是使用者自己的券商 App/網頁，非公開網路截圖

## Candidate Error Or Failure Behavior

- 截圖辨識結果有誤或欄位缺漏時的產品行為——未定，見待釐清問題（SRC-001「尚未在對話中決定」段）
- 美股報價資料源不可用時的降級行為——未定，可能參照既有 `benchmark.py` 對 FinMind 額度用盡時的優雅降級先例（本 repo 既有教訓，非 SRC-001 直接提及，屬 Claude 補充的既有系統慣例）
