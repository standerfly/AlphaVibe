# Spec Kit Input: 進出場分析基礎層（損益追蹤與價位定位）

**Status:** Accepted
**Source Product Spec:** ../../product-spec.md
**Source Scope Decision:** ../../scope-decision.md
**Spec Feature Slug:** entry-exit-foundation
**Handoff Order:** 1

## Feature Summary

為 AlphaVibe 補上「進出場時機分析」的計算基礎：用 FIFO 成本法計算持股
損益（含已出清標的的已實現損益與目前持股的未實現損益），並計算個股
現價在其歷史價格區間中的相對百分位。兩者皆以 MCP 工具形式提供，供
Claude 在對話中直接查詢，取代目前人工交叉比對多個唯讀工具的做法。

## Actors

- **PO（Stander，唯一使用者）**：在對話中查詢持股損益與價位高低位，
  作為加減碼決策的輸入。
- **Claude（MCP 工具呼叫者）**：代 PO 執行查詢並彙整結果。

## Problem and Goal

目前沒有任何工具能回答「這個價位算不算好的進場點」或「我這檔到底賺賠
多少」。既有的浮動損益顯示只存在於個股詳情頁（`report.py:1922-1941`／
`app/routers/stock_detail.py:194-206`），是單一時間點快照、用簡單加權
平均成本（非 FIFO，出清過的標的會失真）、且不是 MCP 工具（Claude 對話
查不到）。既有唯一做「歷史區間定位」的 `_downside_risk`
（`poc/kb-mcp/review_engine.py:146-200`）衡量的是 PER，不是股價本身。

2026-09-01 一輪實際分析中，只能靠人工拼湊多個工具完成，過程中發生資料
單位誤讀事故。目標是把這層計算做成可靠、可查詢的基礎能力。

## In Scope

- FIFO 成本法的持股損益計算，同時涵蓋：
  - 未實現損益（目前持有部位）
  - 已實現損益（已出清標的）
- 個股現價在歷史價格區間中的相對百分位計算（衡量對象為股價本身，
  參考 `_downside_risk` 的歷史百分位邏輯框架）
- 以上兩項的 MCP 工具化（可查單一標的，也可查全部持股）

## Out Of Scope

- 停損/停利門檻設定與觸發判斷（階段B，entry-exit-signals）
- 基本面與價格背離偵測（階段B）
- 營收趨勢判斷範圍擴大（階段B）
- 觸發時的策略建議（階段B）
- 報告頁面（`report.py`／`app/`）的顯示整合（階段B）
- 每日排程整合與主動提醒（階段B）
- 自動下單／自動執行交易（整個功能皆排除）

## User Scenarios

1. PO 在對話中詢問「我的持股進場損益」，系統回傳每檔持股的 FIFO 損益
   金額與百分比（含已實現與未實現），數字與 `get_trade_ledger` 的原始
   交易紀錄可交叉驗證一致。
2. PO 詢問某檔股票「現在的價位算高還是低」，系統回傳該股現價在歷史
   區間的百分位。
3. 某檔股票缺完整歷史價格資料，系統回傳「資料不足，無法計算」而非
   用不足樣本硬算或顯示 0%，且不影響其他欄位與其他持股的計算。
4. 某筆交易紀錄不完整（缺進場價或數量），該檔損益回傳「無法計算」
   並註明缺哪個欄位，其他持股不受影響。

## Functional Requirements

- **FR-E01**：系統應能計算並回傳指定持股（或全部持股）的進場後損益，
  使用 FIFO 成本法，同時涵蓋已實現損益（已出清標的）與未實現損益
  （目前持有部位）。
- **FR-E02**：系統應能計算並回傳指定股票現價在其歷史價格區間中的相對
  百分位。區間長度（例如近 52 週或近 N 年）需與現有 `stock_price_history`
  資料涵蓋範圍一併確認後決定。
- **FR-E07a**：以上功能須以 MCP 工具形式提供，供 Claude 對話直接查詢。
  （FR-E07 的報告頁面整合部分屬階段B。）

## Success Criteria

- PO 能直接查詢到 FIFO 正確計算的損益數字（已實現＋未實現），不需要
  Claude 手動交叉比對多個工具。
- 損益計算結果可與 `get_trade_ledger` 原始交易紀錄交叉驗證一致。
- 股價歷史高低位判斷能被單一工具呼叫取得，不需多輪人工比對。
- 資料不足的情境明確回傳「無法計算」狀態，不產生誤導性數字。

## Constraints and Assumptions

- 沿用既有資料源與既有 MCP 工具/底層函式，不引入新的外部資料源或
  第三方 API。
- 沿用本 repo 既有慣例：Python 3.9 相容、poc 零外部依賴、繁體中文介面。
- 資料不足時的降級行為沿用 `benchmark.py` 既有的優雅降級模式與部位控制
  卡的「算不出來就明講、不要畫 0% 空條」三分狀態原則。
- 本階段為唯讀計算，不涉及任何寫入交易紀錄或下單動作。
- 既有報告頁面的浮動損益顯示邏輯在階段B 才改用本階段的 FIFO 邏輯；
  本階段完成後兩套數字可能暫時並存不一致，屬已知且可接受的過渡狀態。
