**Feature Slug:** broker-statement-import
**Last Updated:** 2026-10-31
**Sources:** SRC-001、SRC-002；Q-001～Q-005

## 每日流程

```mermaid
flowchart TD
    A[國泰寄出日對帳單 Email<br/>交易日約 18:30 起] --> B[排程：讀 Gmail<br/>找國泰對帳單、尚未處理過的]
    B -->|沒有新信| Z[結束，不通知]
    B -->|有新信| B2[依對帳單日期由舊到新排序]
    B2 --> C[用身分證字號開啟 PDF]
    C -->|打不開| F1[標記失敗＋通知 PO]
    C --> D[擷取交割金額／交易明細／庫存明細]
    D -->|格式無法辨識| F2[標記失敗＋通知 PO<br/>不寫入任何資料]
    D --> E[交易明細：名稱→代號<br/>委託書號已存在的跳過]
    E --> G[寫入交易流水表]
    G --> H[庫存明細：更新庫存快照<br/>對帳單為準；比已處理的還舊則不覆蓋]
    G -.->|寫入失敗| F3[整份還原＋通知 PO]
    H --> I[比對：買賣紀錄推算 vs 對帳單庫存]
    I --> J[標記已處理＋通知 PO 摘要<br/>含差異與無法對應的項目]
```

## 每份對帳單的處理狀態

```mermaid
stateDiagram-v2
    [*] --> 待處理: 收到新的對帳單 Email
    待處理 --> 已處理: 解析成功、寫入完成
    待處理 --> 部分完成: 交易已寫入，但有名稱對不到代號等個別問題
    待處理 --> 失敗: PDF 打不開／格式無法辨識
    失敗 --> 待處理: PO 或 Claude 修正後手動重跑
    部分完成 --> 已處理: 補上名稱對應後手動重跑（FR-014）
    已處理 --> [*]
```

- 同一份對帳單（以對帳單日期＋信件識別）只處理一次；重跑不會產生重複資料
  （成交以委託書號防重複、庫存快照以日期覆寫同一天）。
- 「失敗」時**不寫入任何資料**（整份對帳單全有或全無，交易與庫存不可只寫一半）。
- 「部分完成」只用於個別成交無法對應代號：其餘成交與庫存照常寫入，對不到的成交列在
  通知中，待人工處理。

## 驗證期流程（Q-005：連續 3 次一致即結束，之後不定期抽查）

```mermaid
sequenceDiagram
    participant PO
    participant 國泰
    participant Claude
    participant STND as STND 資料庫
    PO->>國泰: 手動申請一段期間的對帳單
    國泰-->>PO: 對帳單
    PO->>Claude: 提供對帳單（遮掉個資）
    Claude->>STND: 查該期間的成交與庫存（連接器）
    Claude-->>PO: 逐筆比對結果（一致／差異與原因）
```
