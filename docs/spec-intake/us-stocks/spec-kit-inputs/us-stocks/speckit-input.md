# Spec Kit Input: 美股獨立投資系統

**Status:** Accepted
**Source Product Spec:** ../../product-spec.md
**Source Scope Decision:** ../../scope-decision.md
**Spec Feature Slug:** us-stocks
**Handoff Order:** 1

## Feature Summary

在 STND（AlphaVibe 對外服務品牌）新增一個獨立的「美股」分頁，支援美股投資的
研究記錄、交易紀錄匯入、股價走勢圖表與關注條件監控。與既有台股「投資」分頁
在分頁、資料表、查詢用 KB 三層完全獨立，不共用、不混合計算。

## Actors

- **Stander**：STND 的唯一使用者，同時是本功能的操作者。單一使用者個人系統，
  無多角色/多使用者權限概念。

## Problem And Goal

使用者投資美股，但目前沒有系統支援——研究討論散落在對話中，交易紀錄只存在
券商 App 截圖，沒有集中管道可以回顧持股現況、追蹤投資立場是否仍成立、或
察覺關注中的個股是否已觸及該重新檢視的門檻。

目標：複製既有台股「投資」分頁證明有效的核心體驗（股價走勢＋進出場點位、
立場記錄、條件監控），但資料與判斷邏輯完全獨立於台股。

## In Scope

- 新增獨立「美股」分頁（STND 導覽新增項目，不併入既有「投資」或「資產」分頁）
- 美股 landing 頁：追蹤清單，每檔顯示現價/漲跌/立場/觸發狀態
- 個股詳情頁：股價走勢圖＋買賣點位標記（視覺比照台股 `StockComboChart` 元件
  風格，資料源與資料表完全獨立）
- 交易紀錄匯入：截圖上傳 → 系統辨識 → 人工核對畫面 → 使用者確認/修正 → 寫入
- 投資立場／研究筆記：使用者與 agent 討論後存入結構化立場（買/賣/觀望＋
  Bear/Base/Bull 情境價格帶＋論點摘要），個股詳情頁可查看完整研究筆記內容
  （STND 內以既有卡片/字體/配色系統原生渲染，內容不因版面密度而砍減）
- 關注條件清單：可設定監控門檻，agent 於使用者互動時查詢最新資料並比對，
  碰觸時標示警示狀態（未觸發/已觸發/資料不足 三態）
- 關注條件觸發時透過既有 Telegram 閘道（`function/stnd-gateway-web`）推播通知
- 視覺規範：漲跌與買賣點位顏色沿用台股既有慣例（紅=漲/買進，綠=跌/賣出）

## Out Of Scope

- 交易紀錄 CSV／報表匯入（僅支援截圖）
- 付費報價 API 方案（僅用免費層）
- 排程自動輪詢報價/關注條件（免費 API 額度不支撐；資料取得是按需，使用者/
  agent 互動觸發）
- 美股與台股資料的任何跨市場彙總計算（合併損益、合併資產總覽等）
- 多使用者/多角色權限設計
- 截圖原始檔的永久保存

## User Scenarios

1. **交易匯入**：使用者上傳一張券商 App 截圖 → 系統顯示辨識出的日期/代號/
   買賣/股數/價格核對表（不論辨識完整度，一律先進核對畫面，未辨識欄位留空）
   → 使用者確認或修正後點擊確認匯入 → 該筆交易出現在對應個股的股價圖買賣
   點位上；使用者取消核對時，暫存截圖與未確認資料一併捨棄，不留痕跡
2. **研究到立場**：使用者與 agent 討論一檔股票的後勢 → agent 產出研究筆記與
   結構化立場 → 使用者確認存入 → 個股詳情頁的「投資立場」卡片顯示立場摘要，
   並可點入查看完整研究筆記（章節、引用來源、情境區間均完整呈現，不壓縮）
3. **關注條件觸發**：使用者與 agent 互動時，agent 查詢某檔股票最新資料 →
   發現碰觸使用者設定的門檻（例如股價跌破 $X、毛利率跌破 Y%）→ 透過 Telegram
   閘道推播通知 → 美股 landing 頁該檔列顯示「已觸發」狀態 → 使用者點入個股
   詳情頁看到具體是哪個條件觸發、目前數值與門檻的對比
4. **資料查無**：agent 互動時查無某檔股票最新資料（含主要報價來源查無或
   額度用盡、備援來源也失敗）→ 關注條件狀態顯示「資料不足」（pending），
   不誤判為「未觸發」，不觸發推播 → 下次互動取得資料後自動轉為正常狀態

## Functional Requirements

- **FR-01** STND 導覽新增獨立的「美股」分頁
- **FR-02** 交易紀錄匯入：使用者上傳截圖 → 系統辨識 → 呈現核對畫面 → 使用者
  確認（可修正欄位）→ 寫入美股獨立交易紀錄表；辨識完全失敗時呈現空白核對表
  由使用者手動輸入全部欄位
- **FR-03** 個股詳情頁股價走勢圖＋買賣點位標記，視覺比照台股 `StockComboChart`
  風格；股價資料由 agent 於使用者互動時呼叫免費報價 API（主要來源 FMP，
  額度用盡或失敗時自動切換備援來源）按需取得，為 EOD（收盤後）資料，非即時
- **FR-04** 研究筆記／投資立場：討論結果存入結構化立場（買/賣/觀望＋
  Bear/Base/Bull 情境價格帶＋論點摘要）
- **FR-05** 個股詳情頁原生渲染完整研究筆記內容（STND 既有卡片/字體/配色
  系統），不因版面密度砍減章節、引用來源或論述完整度
- **FR-06** 關注條件清單：可設定監控門檻（股價、毛利率、NRR 等指標），
  agent 於使用者互動時查詢最新資料並比對，碰觸時標示警示狀態（未觸發 ok／
  已觸發 alert／資料不足 pending 三態）；NRR 等 API 查不到的指標需使用者/
  agent 互動時手動補充
- **FR-07** 美股 landing 頁追蹤清單，每檔顯示現價/漲跌/立場/觸發狀態一覽
- **FR-08** 漲跌與買賣點位視覺色彩沿用台股既有慣例（紅=漲/買進，綠=跌/賣出）
- **FR-09** 關注條件碰觸門檻時，透過既有 Telegram 閘道（`function/stnd-gateway-web`
  「管家」分頁）主動推播通知

## Success Criteria

- 使用者能在美股分頁一眼看出哪些持股/關注股觸發了警示，不用逐檔比對
- 使用者能把跟 agent 討論出的投資立場保留在系統裡，之後回顧不需重新翻找
  對話記錄
- 使用者提供交易截圖後，系統能正確辨識並在人工核對後寫入紀錄，不需逐筆
  手動輸入
- 美股資料與台股資料在分頁、資料表、KB 三層都不互相汙染或混淆

## Constraints And Assumptions

- 美股相關資料表（交易紀錄、立場、關注條件、報價歷史）不得與既有台股資料表
  共用；美股查詢用 KB 必須與既有台股 KB（`mcp__alphavibe-kb__*`）完全獨立
- 幣別一律 USD，不與台股 TWD 混合計算加總
- 單一使用者個人系統，不需要多使用者/多角色權限設計
- 假設交易截圖來源是使用者自己的券商 App/網頁
- 報價/基本面資料透過免費 API 多來源取得（主要 FMP＋備援），使用者/agent
  互動時按需查詢；不做背景排程輪詢，僅用免費層
- 主要來源（FMP）免費方案：250 次/日、免信用卡、含 EOD 股價與損益/資產
  負債/現金流量表；備援來源候選 Alpha Vantage（25次/日，額度緊）或 yfinance
  （非官方、涵蓋較廣、ToS 屬灰色地帶）——最終選定與主/備切換邏輯留待技術
  設計階段決定
- 需要使用者申請個人免費 API key（FMP／備援來源），儲存與管理方式留待技術
  設計階段依本 repo 既有慣例（例如 `finmind_token.txt` 的先例）決定
- 交易截圖不永久保留，僅在辨識/核對流程中暫存，確認或取消後即刪除；只有
  核對後的結構化交易資料永久保存
- 依賴既有 Telegram 閘道（`function/stnd-gateway-web`）提供推播；推播失敗
  不影響 STND 頁面顯示警示狀態（頁面顯示為主、推播為輔）
- 視覺元件風格依賴既有 `web/src/styles/tokens.css`／`app.css`／
  `StockComboChart.jsx` 建立的 STND 設計系統（沿用，非重寫）
- 美股獨立 KB 的具體技術實作方案（另開 MCP 工具 vs 同 DB 加欄位隔離）、
  「結構化內容→STND頁面元件」研究筆記渲染的技術做法，均留待技術設計階段
  決定，僅記錄「必須獨立」「內容不可壓縮」的產品層約束
