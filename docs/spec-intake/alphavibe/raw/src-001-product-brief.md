## 1. 功能概述 (Feature Overview)

AlphaVibe 是一個台股為主、兼顧美股的投資資訊儀表板，專為個人投資者設計。初期供個人使用，未來擴展至少量受信任的朋友群，以 Docker 容器化方式部署於雲端。

**痛點：** 投資資訊分散在 LINE 群組、各投資網站與 Facebook 社群，每天需要手動彙整才能形成完整的市場觀點，耗時且容易遺漏。

**解法：** AlphaVibe 在每個交易日收盤後，收集並彙整分散的訊息來源，產出結構化的總結報告（含來源連結），並由 AI Agent 提出市場觀點與買賣訊號，協助投資者高效完成當日覆盤，為下一個交易日做好準備。

**核心功能面向：** 收集 → 彙整 → 分析 → 建議（市場觀點 + 買賣訊號）

**AI 知識庫特色：** 長期累積特定 LINE 群主（匿名）的市場觀點，建立三層知識庫供 AI Agent 參照：
- **Layer 1 投資哲學**（慢變）：群主的核心方法論，作為 Agent 的 system context
- **Layer 2 個股立場**（每週更新）：結構化個股看法 `{代碼, 立場, 日期}`，由 LLM 自動抽取後人工修正
- **Layer 3 每日評論**（每日 ingestion）：當天發言向量化，供 Agent 語意查詢
- **照片**：v1 跳過，記錄佔位符；未來視需求加入 Vision LLM
- **資料來源**：v1 手動貼入，未來透過 n8n 自動化

**輸出介面：** 單頁式儀表板，報告內容可連結回原始來源；未來規劃自動通知功能。

**即時性：** 不要求即時，以每日收盤後的全面檢視為主要使用情境，速度以排程機制補足。

**持倉檢視：** 預留為未來功能，v1 不在範圍內。

## 4. MVP 範圍 (MVP Scope)

### 4a. 本次要做 (In Scope)
- 手動貼入三來源資料（LINE 群組、LINE 一對一、定錨 email、股癌 Facebook）
- AI 知識庫三層建立：Layer 1 投資哲學、Layer 2 個股立場、Layer 3 每日評論
- 每日收盤後產出結構化報告（市場方向 + 明日策略 + 個股更新）
- 自選股（watchlist）：新增、刪除、檢視，欄位 {code, name, added_date, memo}
- 儀表板：單頁式，自選股以可收合面板呈現於右側/底部

### 4b. 本次不做 (Out of Scope)
- 持倉追蹤（成本價、損益、部位大小）
- 自動爬取或 n8n 自動化
- 照片/圖片解析（Vision LLM）
- 自動通知推播
- 多用戶管理

### 4c. 未來再考慮 (Deferred)
- n8n 自動化資料收集
- 持倉管理與損益追蹤
- 自動通知（LINE / email）
- Vision LLM 處理圖表照片
- 擴展至受信任朋友群的多用戶支援

## 5. 功能需求草稿 (Functional Requirements Draft)

> 描述系統「應該做什麼」，不要寫實作細節。每條需求應可測試。

- FR-001: 使用者可手動貼入來自 LINE、定錨、股癌的原始文字，系統依來源 tag 儲存
- FR-002: 系統可從定錨 email 文字以結構化解析（非 LLM）抽取個股代碼、EPS 財測、定錨觀點
- FR-003: 系統可透過 LLM 從 LINE 訊息抽取群主的個股立場，產出 {code, name, stance, date} 供人工確認
- FR-004: 每日收盤後，系統以單次 LLM call 產出報告，包含：市場方向、明日策略、個股更新（自選股優先）
- FR-005: 使用者可在儀表板新增、刪除、檢視自選股（{code, name, added_date, memo}）
- FR-006: 自選股有新消息時，在報告中優先顯示於第一區；其他今日提及股票顯示於第二區
- FR-007: 報告內容可連結回原始來源片段

## 8. 限制條件與假設 (Constraints & Assumptions)

### 系統設計原則
- **穩定優於速度：** 系統以準確性與穩定性為第一優先，速度透過排程機制補足，不追求即時性。
- **最小化 LLM 請求：** 盡量減少對 AI Agent 的 API 呼叫次數，降低成本與錯誤率。
- **前後端分離：** 系統維持前後端分離架構，介面與邏輯層獨立部署。
- **功能最小化：** 功能以最小可用為原則，每個模組獨立開發與測試後再整合，方便 AI 輔助開發與日後維護。
- **架構文件優先：** 系統架構與模組間溝通文件需完整維護，參數命名保持全系統一致性。

### 部署假設
- 以 Docker 容器化方式部署於雲端。
- 初期單人使用，未來擴展至少量朋友（小規模多用戶）。
