# PO 原始需求 prompt（2026-11-18，原文摘錄；未改寫）

## Purpose（目的）
PO 在 substack.com 追蹤了喜歡的作者；有新文章時 PO 的 Gmail 會收到通知信。PO 要 Mac 自動把這些文章存下來（PO **目前沒有付費訂閱**，所以付費文章只會有摘要／預覽），讓 AlphaVibe 在 claude.ai 對話（台股／美股連接器）中能搜尋並引用。目標：**有效使用資源、方便未來維護**——不要為 Substack 另造一整套平行系統。

## Target（環境與已知事實）
- 環境：macOS Apple Silicon Mac mini；`/usr/bin/python3` 3.9.6（只用標準庫、3.9 相容）；Node 26；Playwright 已有；排程用 launchd；正式環境在 `AlphaVibe-prod`（git worktree，`ops/deploy.sh` 部署）；Gmail 以 IMAP 唯讀＋鑰匙圈取信。
- 010 已驗證經驗（沿用）：低頻守衛、新資料目錄防呆（`article_data_guard`）、外洩掃描與 `no_leak` 測試、固定文字通知、台美連接器共讀同一個唯讀 `articles.db`、MCP 工具數守門（台股 50／唯讀 31／美股 10；新增工具要同步 `server.py`／`server_readonly.py`／`us_stock_mcp_server.py`／兩個守門測試與 Mac 上 `~/.claude` stock-researcher 白名單）、轉寫驗證等級、「驗證不能由產出者自己做」的獨立驗收。
- 要先查證：Substack 公開 RSS／Atom、feed 全文或摘要、付費文章呈現、更新頻率與速率、通知信格式（追蹤轉址不可跟隨）、站方條款對自動存取規定、robots.txt。**不得繞過付費牆、不得登入他人帳號或使用 PO 的 Substack 登入 cookie**；只存公開可見內容。
- 資料與版權：文章只供 PO 個人本機參考，不轉發、不公開；local-first。

## Components（要與 PO 逐題釐清）
1. 取得方式（RSS 為主／Gmail 通知信為輔？）
2. 追蹤清單（來源與新增停用方式，PO 不寫程式）
3. 資料模型與重用（共用 articles.db 加 source，或獨立 substack.db＋新工具；評估守衛、唯讀開庫、備份、健檢、連接器台美一致、來源可信度標示）
4. 內容處理（僅摘要標記、全文與摘要區分、圖片、重複與更新、去重鍵用 URL／GUID）
5. 排程與通知（低頻、睡眠補跑、Telegram 固定文字、失敗與封鎖處理）
6. 維運（備份、健檢、日誌與外洩掃描、回滾、部署、quickstart）

## Function（流程與限制）
- 流程：嚴格走 ADR-0027——先 /prespec（未 Accepted 前不寫程式、不建 specs/）→ PO 審閱 Accepted → Spec Kit（編號 011 起）→ 實作 → 每階段全新 agent 獨立驗收 → PO 同意才合併／部署。功能分支 `function/substack-import`（基底 `function/alphavibe`）。
- 安全與隱私（硬性）：日誌、通知、回報不得含帳密、cookie、token、文章標題與全文（**本條「通知含標題」已被 PO 2026-11-19 決定覆寫，見 PO 決定紀錄**）；對外請求用通用 User-Agent，不得放 PO email 或個資；不登入、不用 cookie；鑰匙圈檢查只用存在性；給 PO 的指令一律 zsh 相容；任何要讀 Gmail／鑰匙圈的真實執行須 PO 在對話中親自同意。
- 低頻與禮貌：請求量最低、遵守 robots.txt、設定逾時與間隔、用條件請求；被擋或異常即停並通知，不重試轟炸。
- 不要做：不繞過付費牆、不抓付費全文、不自動轉發內容、不在 pre-spec 階段寫程式、不改 010 既有行為（共用資料庫遷移必須向後相容且可回滾）、不部署前未備份。
- 環境注意：先 pwd 與 git status；Python bytecode 快取（`模組.__cached__`）；macOS `/var`→`/private/var` 用 `os.path.realpath`；測試用獨立資料目錄。
