# 資料模型說明：方案 C 與 010 隔離（011）

**Feature Slug:** substack-import
**Last Updated:** 2026-11-19（追加決定後修訂）
來源：SRC-002 決定4、8、11；SRC-001 Components 3／4；SRC-004。本檔寫產品層級資料意義，不定義實際欄位與 SQL（留給 plan）。

## 1. 方案 C 與 010 隔離

| 項目 | 規定 |
|------|------|
| 儲存位置 | 獨立資料庫 `substack.db` 與獨立圖片目錄，位於同一資料根目錄下 |
| 010 的 `articles.db` | 不新增、修改、刪除任何內容或結構；不加欄位、不加來源標記 |
| 查詢 | 既有 `search_articles`／`get_article` 內部同時查兩庫，結果標示來源；定錨文章的結果與行為不變 |
| 寫入 | 只有 011 的排程與即時取得寫 `substack.db`；寫入受 011 專屬鎖保護 |
| 防誤撈 | 011 不寫入 010 流水線讀取的資料；測試證明 011 文章與圖片不會被 010 排程轉寫流水線選取（FR-009）。手動少量轉寫（FR-010）的實作路徑待規格（Q-115），不得因此改變 010 行為 |
| 舊庫唯讀相容 | `substack.db` 不存在時，搜尋只回定錨結果、不報錯、不建庫；舊版 `articles.db`（無新欄位）唯讀查詢不報錯 |
| 回滾 | 刪除或還原 `substack.db` 與圖片目錄即回到 011 之前；因不動 `articles.db`，無需遷移回滾 |

## 2. 資料實體（產品語言）

| 實體 | 說明 | 關鍵屬性 |
|------|------|----------|
| 追蹤作者 | 設定檔中的一位出版作者 | 出版名稱（顯示用來源）、subdomain 或網域、啟用／停用 |
| 文章 | 一篇 Substack 文章 | guid、URL（去重鍵）、標題、作者／出版名稱、發布時間、全文或預覽內容、完整度（全文／僅預覽）、抓取時間 |
| 文章圖片 | 文章內的圖片 | 所屬文章、圖位序號、圖說／alt、本機檔案、狀態（待下載／已下載／缺圖）、轉寫結果（若手動轉寫過） |
| 輪詢狀態 | 每位作者的最近輪詢狀況 | 上次請求時間（最小間隔依據）、上次 ETag、上次結果狀態 |

## 3. 文章狀態與生命週期

| 狀態 | 意義 | 轉換 |
|------|------|------|
| 新發現 | feed 出現且未存過 | → 已存（全文／僅預覽） |
| 已存－全文 | 免費文章完整儲存 | 終態（MVP 不更新，Q-109） |
| 已存－僅預覽 | 付費文章預覽儲存 | 終態（不嘗試升級為全文；PO 無付費訂閱） |
| 略過 | 首次執行早於 14 天窗，或重複 | 不寫入 |
| 寫入失敗 | 單篇失敗 | 回到「新發現」，下次再試 |

圖片狀態：待下載 → 已下載／缺圖；缺圖由排程補下載（→ 已下載）；已下載圖片可被手動轉寫（→ 已轉寫）。完整狀態轉換見 workflow-and-state-model.md。

## 4. 保留與清理

- 文章：MVP 不自動刪除；停用作者不刪已存文章（草稿推論，待 PO）。
- 圖片：保留期限未決（Q-114）；只回報占用量，不設閾值（Q-011）。
- 備份：是否納入每日備份與健檢待 Q-111。
- 付費內容：只存公開預覽；不存任何登入後內容。

## 5. 去重與首次回補規則

- 去重鍵：guid 與 URL；任一已存即視為重複（兩者衝突時的處置待規格，非阻擋）。
- 首次執行：只收發布時間在「首次執行日前 14 天」內者；首次執行日定義為首次真實成功執行當日（若首次執行中途失敗，重跑沿用同一基準日，待規格確認）。
- 之後執行：收 feed 內所有未存過的文章（feed 上限 20 篇，Q-110）。

## 6. 相容性

- 010 既有測試與守門（除 parity 例外）全數保持通過。
- 不改共用資料庫結構，故無需資料庫遷移。
