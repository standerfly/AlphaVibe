## 1. 外部整合

| 對象 | 用途 | 時序 | 失敗語意 |
|---|---|---|---|
| Gmail（PO 信箱） | 取得國泰對帳單 Email 與附件 | 每交易日晚間排程讀取；當晚沒收到則下次排程再找（不遺漏、不重複） | 無法連線：本次略過，下次排程重試；連續失敗通知 PO |
| 國泰對帳單 PDF | 資料來源 | 交易日約 18:30 起寄送（樣本 19:12） | 打不開／格式變動：整份失敗、不寫入、通知 PO |

- 只認寄件人 `e-notification@ebill1.cathaysec.com.tw` 且主旨為「國泰綜合證券日對帳單」
  的信，其他信一律忽略（避免偽造信件寫入資料）。
- 國泰改版造成格式變動時，視為「格式無法辨識」，不猜測欄位。

## 2. 資料對應（Q-002：對帳單是標準）

| 對帳單欄位 | STND 資料 | 備註 |
|---|---|---|
| 交易明細：成交日期（交割金額區塊） | 交易日期 | |
| 商品名稱 | 股票代號 | 先對同份庫存明細，再用既有名稱→代號解析；都對不到則該筆不寫入、列入通知 |
| 類別（集買／集賣…） | 買賣別 | 沿用既有交易明細表的類別判讀 |
| 成交股數、單價 | 股數、價格 | |
| 手續費、交易稅 | 交易成本 | 新資訊；既有交易流水表沒有這兩欄，是否保存由技術規格決定 |
| 委託書號 | 防重複唯一鍵 | 與既有手動匯入共用同一套防重複；三種寫法（`kABCD00`／`k-ABCD-00`／`kABCD`，示意）以「前綴＋4 碼＋2 碼序號」比對，忽略連字號、大小寫不轉換、無序號視為 `00`（Q-010） |
| 庫存明細：代號、名稱、集保股數 | 庫存快照 | 對帳單日期為快照日期；**完整持股**，未列出的股票視為已無持股（Q-013：全部台股都在國泰）；較舊日期的對帳單不覆蓋較新庫存（FR-013） |
| （無平均成本） | 庫存成本 | 已有成本沿用，當天買進依加權平均更新、賣出不變；沒有成本的用買賣紀錄推算；算不出來留空並通知（每檔只通知一次） |

## 3. 冪等與稽核

- 同一份對帳單重複處理，結果與處理一次相同（委託書號防重複；同一天的庫存快照覆寫）。
- 一份對帳單的成交與庫存寫入是同一個交易（transaction）：中途失敗全部還原（FR-009）。
- 每份對帳單的處理紀錄（日期、狀態、寫入筆數、差異、錯誤訊息）要保存，供驗證期比對與
  事後查詢。
- 自動匯入的資料要能與手動匯入區分（來源標記），方便追查。

## 4. 安全與隱私（Q-004）

- 身分證字號（PDF 密碼）與 Gmail 應用程式密碼：只存在 PO 的 Mac「鑰匙圈」，不進 repo、
  不寫進設定檔、不出現在對話或通知。
- 信箱權限只需讀取；只處理國泰對帳單，不讀其他信件內容。
- 解密後的 PDF 與擷取的文字不另外留存（或只在處理期間暫存，處理完刪除）。
- 對帳單內的個資（姓名、帳號、地址）不寫入資料庫。

## 5. 監控與手動補救（Q-003：Telegram 通知）

| 狀況 | 通知 PO | 手動補救 |
|---|---|---|
| 成功 | 摘要：日期、成交筆數、庫存檔數、差異 | 無 |
| 部分完成（名稱對不到代號） | 列出對不到的成交 | 在 claude.ai 告訴 Claude 正確代號後補寫 |
| 失敗（PDF 打不開、格式變動） | 錯誤原因 | 修正後手動重跑該份對帳單 |
| 庫存與買賣紀錄推算不一致 | 列出差異股票 | 確認原因（配股、紀錄起點前的持股等） |
| Gmail 存取失敗 | 每次都通知，同一錯誤一天最多一次 | 檢查應用程式密碼是否失效 |
| Telegram 送不出去 | 每日健康檢查回報 | 檢查 Telegram 設定 |
| 排程本身沒跑（Mac 睡眠等） | 既有每日健康檢查（04:00）納入本排程 | 喚醒後自動補跑 |
