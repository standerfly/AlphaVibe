## Problem And Goal

PO 在 Substack 追蹤了喜歡的作者，目前沒有付費訂閱。PO 希望這些作者的新文章自動存到 Mac，並能在 claude.ai 對話（台股／美股連接器）中搜尋與引用；看到新文章時也能請 Claude 立刻取得。目標是有效使用資源、方便未來維護：不為 Substack 另造一整套平行系統，日常排程不消耗模型訂閱額度，不登入、不繞付費牆。第一版另須能對少數幾篇文章手動跑一次圖片轉寫，以驗證流程與功能。（SRC-001 Purpose；SRC-002）

## Business Context And Priority

- Priority: 個人研究輔助功能；優先級 raw 未明述，由 PO 於審閱時標註。
- Timing: 緊接 010（定錨文章匯入）之後，編號 011。（SRC-001 Function）
- Business value: 讓 PO 與 Claude 討論投資時可引用自己追蹤的作者觀點，免去手動整理。（SRC-001 Purpose）

## Actors

- PO（Stander）：追蹤作者、審閱結果；親自確認安裝排程，以及任何登入、鑰匙圈、消耗訂閱用量的動作（含手動轉寫）。
- Claude（Mac Claude Code、claude.ai 連接器）：搜尋、讀取、修改追蹤清單設定檔、代為觸發即時取得與手動轉寫。
- 排程（每日 22:00）：無人值守地輪詢與存檔。

## MVP Scope

### In Scope

見 scope-decision.md「MVP In Scope」；摘要：RSS 唯一來源、獨立 `substack.db`、首次 14 天、每日 22:00＋獨立鎖、免費全文／付費預覽、圖片下載（即時取得同步下載、失敗由排程補）與圖位標記、**對少數幾篇文章手動轉寫一次（限手動、少量）**、含作者＋標題的通知、空間現況回報、即時取得雙入口與通用寫入工具、雙庫並查搜尋與來源可信度標示、token 排程間隔過短提醒。

### Out Of Scope

Gmail 通知信、登入／cookie／繞付費牆、抓單篇網頁、改動 `articles.db`、排程階段呼叫模型（含排程化轉寫）、自動轉發、市場標籤、空間閾值、全量歷史回補。完整清單見 scope-decision.md。

### Deferred

市場標籤與依市場隔離搜尋、文章修改後更新偵測、**排程化（自動）圖片轉寫**、漏文偵測、圖片保留期限。（手動少量轉寫已移入 MVP，見 FR-010。）

## Functional Requirements

**取得與來源**

- FR-001 系統只從追蹤作者的 Substack 公開 RSS 取得內容；不使用 Gmail 通知信、不登入、不使用任何 cookie、不使用私人 feed、不繞付費牆。（CFR-01、CFR-10）
- FR-002 追蹤清單存於設定檔，初始包含 FOMO研究院電子報與大叔美股筆記；PO 透過與 Claude 的對話新增或停用作者，不需編輯程式碼。停用的作者不再被輪詢，其已存文章保留。（CFR-02、CFR-03；「已存文章保留」為本草稿推論，raw 未明述，待 PO 確認）
- FR-003 每個作者每次執行至多發出一次 feed 請求，使用條件請求；請求帶通用識別（不含 PO 個人資訊）、設定逾時、遵守 robots.txt。（CFR-25）

**儲存與去重**

- FR-004 文章存入獨立的 `substack.db`；不新增、修改、刪除 `articles.db` 的任何內容或結構。（CFR-04）
- FR-005 以 guid／URL 判斷重複，同一篇文章只存一份；重複執行不產生重複紀錄。（CFR-05）
- FR-006 首次執行只收「首次執行日前 14 天」內發布的文章；此後每次收 feed 中尚未存過的文章。（CFR-06）
- FR-007 免費文章存全文；付費文章只存公開預覽，並標記「僅預覽」。判斷規則為三類：**P 預覽**＝`content:encoded` 結尾為固定「Read more」連結段落；**F 全文**＝無該尾端且有足夠純文字；**N 非文字**＝無該尾端且幾乎無文字或僅有播放器。**無法確定者一律存為「僅預覽」並標示，寧可誤標**；**不得以文章長度判斷預覽**（已觀察到長文也帶 Read more 的反例，見 SRC-005）。風險：結尾標記是推論、非站方保證，站方改版會使判斷整批失準，見 FR-031；遇到模式不符的文章依上述三類逐項判斷，不另設隱性預設值。（CFR-09；SRC-002「追加決定（Q-103／Q-104 調查後）」節；SRC-005；Q-103）
- FR-008 文章圖片下載至本機圖片目錄；不送模型分析；內文保留圖位標記（含圖說／alt）。圖片下載失敗不影響文章存檔，該圖記為缺圖。**排程執行時，除抓新文章外也補下載先前缺圖的圖片**；即時取得時圖片同步下載，下載失敗者留給排程補下載。（CFR-11、CFR-27；SRC-002「追加決定」第5題；不影響存檔為草稿建議，見 Q-114）
- FR-009 011 文章預設不進入 010 排程轉寫流水線；須有自動化測試證明 011 文章不會被流水線選取（手動少量轉寫見 FR-010，不改變此預設）。（CFR-12）
- FR-010 第一版須能對**少數幾篇**文章手動跑一次圖片轉寫，供 PO 驗證流程與功能。限制：僅手動觸發、不排程；會消耗訂閱額度，故須 PO 當下對話親自確認；不得改變 010 既有行為與 `articles.db`；011 文章仍預設不進 010 排程流水線（FR-009 測試要求不變）。PO 已確認此解讀（Q-115）。**試跑對象規則**：判定為 F（全文）類、較近期的文章，每位作者至少 1 篇、至多 3 篇（2026-11-19 實測候選：FOMO 3 篇、大叔 1 篇，SRC-005）。實作路徑（例如重用 010 低階轉寫模組指向 `substack.db`）**不在本基線寫死**，由規格階段判定並證明不影響 010（Q-122）。（CFR-11、CFR-26；SRC-002「追加決定」第2題）

**排程與執行**

- FR-011 排程每日 22:00 執行一次。**05:00～18:00 時窗只約束會消耗 AI agent token 的工作**；RSS 抓取、即時取得與 22:00 排程不受此限。手動觸發的 token 消耗工作是否受限待確認（Q-116）。若 Mac 睡眠錯過 22:00，補跑規則見 schedule-and-locks.md（待 PO 確認）。（CFR-07、CFR-28；SRC-002 決定6 與「追加決定」第4題；SRC-001 睡眠補跑）
- FR-012 011 使用自己的獨立執行鎖，只寫 `substack.db`；排程與即時取得共用此鎖，同時刻只有一個執行寫入。（CFR-08、CFR-16）
- FR-013 排程階段不呼叫任何模型、不消耗 claude.ai 訂閱額度（手動轉寫見 FR-010，不屬排程）。（CFR-13）
- FR-014 須由 PO 在當下對話親自確認的範圍為 PO 原範圍：**登入、鑰匙圈、消耗訂閱用量**，以及**安裝排程**。RSS 輪詢（排程與即時取得）不另逐次確認；不由別的對話代為同意。（CFR-22；SRC-002「追加決定」第1題，Q-101 已答）

**通知、日誌與空間**

- FR-015 有新文章時以 Telegram 發送固定格式通知，含作者與標題；日誌與錯誤訊息不得含標題、全文、帳密、cookie、token；並有外洩掃描與對應測試。（CFR-14；SRC-001 安全隱私）
- FR-016 健檢與通知回報剩餘硬碟空間、`substack.db` 與圖片目錄的占用量；只回報現況，不判定異常、不設閾值。（CFR-15）
- FR-017 異常（被擋、逾時、解析失敗）時停止該次對該作者的請求、發出告警，不連續重試。（CFR-25）

**即時取得**

- FR-018 即時取得立即輪詢一次 RSS，可指定單一作者或全部；與排程共用鎖、去重與資料庫；只認 RSS，不抓單篇網頁；若 feed 尚未出現新文章，回報「稍後再試」。（CFR-16）
- FR-019 同一作者兩次輪詢之間有最小間隔守衛，**任何輪詢（排程或即時取得）都計入**；即時取得在間隔內被拒絕並回報還需等待多久；排程輪詢落在間隔內則跳過並記錄、不算失敗。間隔數值為**預設 30 分鐘、可隨時調整的設定，不寫死**（PO 原話「同意，但可以隨時調整。」）；調整方式由規格階段定。（CFR-16；Q-102；Q-121）
- FR-020 即時取得有兩個入口：Mac 上的 Claude Code 對話與 claude.ai 連接器（含手機）。（CFR-17）
- FR-021 連接器入口是通用寫入工具，台股與美股連接器都提供、行為逐字相同；不接受網址參數；只寫 `substack.db`（與圖片目錄）；不列入唯讀白名單。（CFR-18）
- FR-027 新增寫入工具不得破壞 010「文章通道唯讀」既有守門：`article_tools` 以唯讀開庫、查詢不寫 `alphavibe.db`／`us_stocks.db` 的既有測試須維持通過。須**另行證明**守門未被破壞（寫入工具與唯讀查詢路徑分離、唯讀開庫不因新增工具而放寬），列為驗收要求。（CFR-29；SRC-004）
- FR-028 即時取得工具須在連接器逾時內有回應：因同步下載圖片可能逾時，須有「逾時內回報進度或分段」的產品行為（能完成回完整結果；來不及則回已存篇數、剩餘圖片交排程補）；具體機制與逾時上限待規格階段（Q-118）。（CFR-30；Q-119）
- FR-022 工具數量守門：守門數字以合併當下 `function/alphavibe` 實際值為準：011 為台股／美股各 +1、唯讀不變（撰寫時 2026-11-19 實測基準：台股 50、美股 10、唯讀 31，僅為背景資訊）；連接器一致性測試僅對該工具名稱放寬並新增專屬測試，其餘既有測試不得放寬。011 tasks 階段須在合併當下重算守門數字（遠端分支 `origin/claude/substack-article-discussion-8c62eh` 若先合併，台股基準會變 52、唯讀 33，見 Q-104）。（CFR-19）

**搜尋與閱讀**

- FR-023 既有 `search_articles`／`get_article` 同時涵蓋定錨文章與 Substack 文章；每筆結果標示來源（出版名稱），Substack 付費預覽標示「僅預覽」。（CFR-20）
- FR-024 第一版不提供市場（台／美）標籤；新增台股作者只需在設定檔多一行。（CFR-21）
- FR-029 來源可信度標示：Claude 引用 Substack 作者意見時，須標明來源（作者／出版名稱）與完整度——P 預覽與無法確定者標「僅預覽」、F 全文標全文、N 非文字標「非文字」（判斷規則見 FR-007），讓 PO 能分辨這是第三方作者意見、且內容是否完整；搜尋與讀取結果須帶足以支援此標示的資訊。（CFR-31；SRC-001 Components 3「來源可信度標示」）
- FR-025 定錨文章的查詢結果與行為不得因本功能改變；舊版資料庫（尚無新欄位）的唯讀查詢須相容。（CFR-23）

**維運**

- FR-026 提供備份、健檢（含上次成功時間、請求失敗統計）、日誌輪替、回滾與部署說明；`substack.db` 與圖片目錄是否納入備份／健檢待 PO 確認（Q-111）。（CFR-24）
- FR-030 會消耗 AI agent token 的排程之間（含 010 的 23:40 流水線）間隔過短時，系統須**提醒 PO 修改**；提醒方式為健檢／通知，**不自動改排程**。『過短』的數值 PO 未給，待規格階段與 PO 定（Q-117）。011 的 22:00 排程本身不消耗 token，與 12:30／23:00／23:40 的錯開見 schedule-and-locks.md。（CFR-32；SRC-002「追加決定」第3題）
- FR-031 預覽比例異常提醒：健檢須在「全文（F）占比相較近期突然異常」時提醒 PO（例如站方改版使結尾標記消失或全面出現，導致判斷整批失準）；**只報現況與提醒，不自動處置**（不改判、不停止匯入）；『異常』的數值待規格階段與 PO 定。（CFR-33；SRC-002「追加決定（Q-103／Q-104 調查後）」節；Q-103 風險）
- FR-032 價值說明（非行為要求）：依 2026-11-19 實測，現有兩個作者近 40 篇中約 35 篇為僅預覽，即本功能存下的內容多數是預覽而非全文；PO 已知悉並決定繼續（PO 原話「結果正確，011要繼續。」）。（CFR-34；SRC-005）

## Acceptance Scenarios

1. **首次執行**：設定檔含兩位作者、庫為空 → 執行（RSS 輪詢不需逐次確認，安裝排程須 PO 親自確認）→ 只存發布日在前 14 天內的文章（約 25 篇）、各篇有來源與免費／僅預覽標記；再執行一次，文章數不變。
2. **每日排程**：22:00 有新文章 → 存入庫，Telegram 通知含作者與標題；日誌不含標題；無新文章 → 不通知，日誌記錄「無新文章」。
3. **付費文章**：feed 內文只有預覽與訂閱提示 → 存入並標「僅預覽」；claude.ai 搜尋結果顯示「僅預覽」。
4. **即時取得（連接器）**：PO 在手機 claude.ai 要求取得某作者最新文章 → feed 已出現則存入、**圖片同步下載**並回報；下載失敗的圖留給排程補；未出現則回報稍後再試；間隔內重複要求則被拒並說明；若圖片多到可能逾時，工具在逾時內回報已存篇數與進度（FR-028）。
5. **即時取得與排程同時**：兩者撞時，後到者等待或回報忙碌，不產生重複紀錄。
6. **被擋**：feed 回 403／429 → 該作者本次停止、告警、不重試；其他作者不受影響。
7. **新增／停用作者**：PO 在對話要求新增作者 → Claude 修改設定檔 → 下次執行納入；停用則不再輪詢。
8. **不影響 010**：011 全流程跑完後，`articles.db` 內容與結構不變；010 既有測試全過；011 文章不出現在 010 排程轉寫流水線待處理清單。
9. **工具守門**：台股與美股工具數各比合併當下基準 +1、唯讀數不變（基準以合併當下實際值為準，見 FR-022）；唯讀白名單不含即時取得工具；兩連接器該工具輸出逐字相同。
10. **空間回報**：健檢輸出含剩餘空間、`substack.db` 與圖片目錄占用量，不含「異常」判定字眼。
11. **舊庫相容**：用沒有 011 新欄位的舊版 `articles.db` 執行雙庫搜尋，定錨結果與先前相同、不報錯。
12. **手動轉寫試跑**：試跑對象為判定為 F（全文）類、較近期的文章，每位作者至少 1 篇、至多 3 篇（目前實測候選：FOMO 3 篇、大叔 1 篇）。**試跑通過標準**：(a) 流程跑完；(b) 轉寫結果可被搜尋與引用；(c) 010 既有行為與 `articles.db` 前後不變（010 既有測試通過、011 文章仍不被 010 排程流水線選取、排程未被安裝或改動）；(d) 額度消耗已經 PO 當下親自確認；(e) 試跑結果有紀錄（對象篇數、成敗、消耗）。
13. **圖片補下載**：某篇即時取得時有圖下載失敗 → 文章與其他圖已存、失敗圖記缺圖 → 下次排程補下載成功後狀態轉為已下載。
14. **時窗**：RSS 輪詢、即時取得、22:00 排程在任何時間都可執行；會消耗 AI agent token 的排程若與另一個 token 排程（如 23:40 流水線）間隔過短，健檢或通知提醒 PO 修改，且不自動改排程。
15. **來源可信度標示**：Claude 引用 Substack 文章時標明作者／出版名稱，付費預覽另標「僅預覽」。
16. **輪詢互計間隔**：即時取得剛輪詢過某作者 → 排程在最小間隔內輪詢同作者被跳過並記錄，不告警；反之排程輪詢後的即時取得在間隔內被拒並說明。
17. **寫入工具不破壞唯讀守門**：新增即時取得工具後，010 既有「文章通道唯讀」測試（唯讀開庫、不寫 `alphavibe.db`／`us_stocks.db`）全數維持通過，另有證據顯示唯讀查詢路徑未被放寬。

## Success Criteria

- SC-001 兩位初始作者的新文章，最遲於下一次 22:00 排程後可在 claude.ai 搜尋到。
- SC-002 重複執行 N 次，文章數相同（去重正確率 100%）。
- SC-003 011 文章零筆進入 010 排程轉寫流水線；排程執行模型呼叫數為 0（手動轉寫不計入排程）。
- SC-004 010 既有測試全數維持通過，唯一放寬為 parity 測試對新工具的例外。
- SC-005 日誌與錯誤訊息經外洩掃描無標題、帳密、cookie、token。
- SC-006 「僅預覽」判斷依 FR-007 三類規則，無法確定者一律標「僅預覽」（寧可誤標）；實作後以真實 feed 樣本驗證三類分類無漏標；全文比例異常時健檢有提醒（FR-031）。
- SC-007 即時取得單次回應含明確結果（新增 N 篇／無新文章／稍後再試／間隔內被拒），且在連接器逾時內必有回應。
- SC-008 手動轉寫能對少數幾篇文章成功跑完一次，且 010 既有測試與 `articles.db` 比對無差異。

- 假設：PO 無付費訂閱，不會改變此情況；若日後訂閱，不在本範圍。
- 邊界規則一律分類別明寫，不使用「拿不準就填 X」。（SRC-001 踩坑）
