# Spec Kit Input: 機票掃描分頁

**Status:** Draft
**Source Product Spec:** ../../product-spec.md
**Source Scope Decision:** ../../scope-decision.md
**Spec Feature Slug:** flight-scan-page
**Handoff Order:** 1

## Feature Summary

在 STND 新增「機票」分頁，讓使用者建立外站四段票的查詢條件，由系統在
指定的出發區間內抽樣日期並掃描票價，回傳按價格排序的「日期＋外站」組合。
**日期是輸出而非輸入**：使用者只給區間與行程天數，不指定確切日期。

## Actors

- 個人使用者（單一使用者，無角色分層）：建立查詢條件、檢視結果、手動觸發重掃

## Problem and Goal

外站四段票（外站→台北→目的地→台北→外站）能顯著壓低長程票價，但價格同時
受外站、四段各自的日期、以及各段間隔影響，人工窮舉不可行。目標是讓使用者
給出粗略條件後，直接得到按價格排序的可行組合。

## In Scope

- 分頁骨架與手機可用的版面
- 查詢條件的建立、列出、刪除（目的地、外站多選、出發區間、行程天數、
  第1段提前策略、排除月份、目標價欄位）
- 出發日期抽樣與四段票掃描
- 第1段提前策略：不拉遠／約 3 個月／約 5 個月／自動避開指定月份
- 系統為每個主行程日期各自挑選可行的提前天數
- 台北→外站接駁票估價顯示（標示為估算值，不參與排序以外的判定）
- 結果排序與呈現（主行程起訖、外站、四段票價、航空、第1段日期與提前天數）
- 背景掃描：速率守衛、超量時裁切並排隊、進度與狀態顯示
- 已查組合不重複查詢
- 手動觸發重掃
- 每筆結果的外部查價連結（四段票、接駁票）
- 票規風險提示（第1段不可 no-show；僅經濟艙有意義）
- 查詢用量與剩餘配額顯示，並標明限制值是實測或推估
- Google Flights 原生價格追蹤的操作說明與主行程連結

## Out of Scope

- 定期自動重掃與達標通知（屬 flight-price-tracking）
- 訂票與付款
- 多使用者與權限
- 拆票自組
- Skyscanner 等站台的程式化抓取
- 商務艙查詢
- 價格趨勢圖與歷史走勢

## User Scenarios

1. 使用者建立條件「布拉格／成田＋沖繩／2027-04～2027-06／12 天／自動避開暑假／
   目標價 38,000」，掃描完成後看到按價格排序的組合清單。
2. 使用者全程未輸入任何具體出發日，系統仍回傳可行日期建議。
3. 條件含 24 筆組合超過單時段配額，系統完成可執行量後顯示
   「已完成 N／24，剩餘將於約 N 分鐘後接續」，下個時段續掃且不重查。
4. 選「自動避開暑假」後，所有結果的第1段與主行程皆不落在 6–8 月；
   找不到可行提前天數的日期被跳過並說明原因。
5. 掃描途中連續 3 筆逾時，系統中止本批、保留已完成結果、顯示軟封鎖提示，
   且不再發出請求。
6. 掃描到一半服務被重啟，重新觸發後只查未完成的組合。

## Functional Requirements

對應 product-spec 的 FR-01～FR-11、FR-15～FR-18。逐條見來源文件；本包的
驗收以上述使用者情境為準。

關鍵可測條件：
- 未輸入具體日期即可得到排序結果
- 「自動避開」模式下，所有結果的第1段月份皆不在排除清單內
- 同一次掃描中，不同主行程日期可有不同的提前天數
- 重跑同一條件時，已有結果的組合不再發出請求
- 超量時顯示已完成筆數、總筆數與預估接續時間
- 服務中斷後重新觸發，只查未完成者

## Success Criteria

- 使用者不需輸入任何具體日期即可取得按價格排序的日期建議
- 不訂閱任何付費服務即可完整使用
- 系統回報的價格與人工在 Google Flights 核對的價格一致（抽驗 2 組，誤差 0）
- 手機瀏覽器可開啟並檢視結果
- 掃描被速率限制中斷時不遺失已完成結果

## Constraints and Assumptions

- 不得產生金錢成本；付費 API 路徑僅備援且需使用者自備 key
- 查價有速率上限，大批掃描須跨時段分批；目前設定值為保守推估、未經長期驗證
- 不得程式化抓取 Skyscanner（robots.txt 明確禁止），僅可產生連結
- 不得以更換 IP、代理輪替或偽造指紋等方式規避封鎖
- 第1段不可 no-show，否則後三段全部失效（需 UI 提示）
- 僅經濟艙有意義；商務艙在多城市查詢會跳艙翻倍
- 系統顯示的任何限制數字須標明是實測值或推估值
- 外站與目的地偏好會變動，必須是可調設定
- **不重寫演算法**：直接 import 既有 `poc/kb-mcp/flight_search.py`
  與 `poc/kb-mcp/scraper/`（已完成，97 測試）
- 資料層使用獨立 store ＋ 獨立 db 檔，不與投資資料共用
- 配額不足與被封鎖不是 HTTP 錯誤，而是正常回應中的狀態值

## Source Decisions

- 日期為輸出而非輸入
- 抽樣掃描取代整月全掃（速率上限所致）
- 第1段間隔為可調偏好，非硬條件
- 接駁票須顯示（第1段須自費飛到外站）
- 外站與目的地為可調設定
