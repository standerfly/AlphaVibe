## 5. 會消耗 AI agent token 的排程間隔提醒（PO 追加要求）

- 要求：會消耗 AI agent token 的排程之間（含 010 的 23:40 流水線）間隔過短時，系統須**提醒 PO 修改**；提醒方式為健檢／通知，**不自動改排程**。（SRC-002「追加決定」第3題）
- 『過短』的數值 PO 未給（Q-117），規格階段與 PO 定。
- 011 排程本身不消耗 token，因此不納入此間隔計算；手動轉寫為手動、不排程，亦不納入排程間隔計算（但消耗用量須 PO 當下確認）。

## 6. 即時取得與排程互計最小間隔

- 同一作者的最小輪詢間隔（數值 Q-102）以「任何輪詢」為準：排程輪詢與即時取得輪詢**共用同一個『上次請求時間』**。
- 即時取得落在間隔內：拒絕並回報還需等待多久，不發請求。
- 排程輪詢落在間隔內（例如 PO 剛在 21:50 即時取得）：該作者本次**跳過並記錄，不算失敗、不告警**，下次排程再試。
- 304 條件請求也算一次請求（仍會打到站方）。
- 排程與即時取得共用 011 鎖（第 3 節）；先到者先做，後到者回報忙碌（即時）或放棄該次（排程）。
