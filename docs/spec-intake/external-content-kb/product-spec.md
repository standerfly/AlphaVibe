**Status:** Accepted
**Feature Slug:** external-content-kb
**Function Branch:** function/external-content-kb
**Product Owner:** Stander
**TPM:** Stander
**Accepted At:** 2026-11-25
**Acceptance Evidence:** PO（Stander，同時為 TPM）於 2026-11-25 對話中明確回覆「Accept」；阻擋項 Q-003/005/009/013/014 皆已有 PO 回覆（raw/2026-11-20-po-decisions-in-conversation.md）；三輪獨立驗收記錄見 clarification-log.md 與 raw 補記

## Problem And Goal

PO 看過的 YouTube 影片、Podcast、文章常有參考價值，但目前只能靠記憶或重看。評論庫（Layer 3）只適合短評，
且中文全文查詢需 ≥3 字，不適合存逐字稿。目標：把外部內容的**全文**納入 AlphaVibe，讓 PO 在投資討論時能用
Claude 查詢並引用，且每次引用都清楚標明這是「作者個人觀點，未經查證」。（SRC-001）

## Business Context And Priority

- Priority: 中（知識庫工作流的內容來源擴充；PO 已有首個實例 EP466 待用）
- Timing: 無硬性期限；EP466 逐字稿由 PO 備妥後即可驗收（SRC-001、SRC-002）
- Business value: 討論投資時可回溯到原始內容與出處，降低「憑印象引用」的風險

## Actors

- PO（Stander）：提供連結與逐字稿、確認摘要、查詢並引用內容。
- Claude（本機 Claude Code 與 claude.ai 連接器兩種環境，皆為非唯讀端）：代 PO 執行匯入與查詢，產出摘要草稿供 PO 確認。


## MVP Scope

### In Scope

- 獨立的外部內容庫（不混入評論庫、定錨文章庫、Substack 庫）。
- 三種來源：YouTube、Podcast、文章；每筆含全文與中繼資料。
- **收件匣資料夾進件**（Q-002）：PO 把逐字稿存成檔案放進資料匣 `poc/data/inbox/`（Q-019），在 claude.ai 或本機 Claude Code 說「匯入」，系統自行讀檔入庫，逐字稿不經模型輸出。
- claude.ai 直接收全文：僅作短文備援，須標明耗輸出 token。
- 全文檢索與取全文；搜尋回傳命中片段、取全文可指定段落範圍（降低 token）。
- 去重（Q-003）、更新全文、刪除單筆（Q-013）。
- 摘要與全文分開，摘要經 PO 明確同意才入庫（Q-005）。
- 查詢工具在台股與美股兩個連接器都提供；寫入類只在非唯讀端（claude.ai 連接器與本機 Claude Code；Q-009）。
- 專案指示更新：討論投資時先搜尋外部內容庫；內含三句話使用說明與 Google AI Studio prompt 範本（Q-020、Q-021）。

### Out Of Scope

- 評論庫既有 3 筆 EP466 摘要的刪除／遷移（Q-015，PO 另行決定）。
- 修改定錨文章庫、Substack 庫的任何資料表或程式。
- 任何未經 PO 確認的自動摘要寫入。

### Deferred

- 自動抓字幕、Whisper 轉錄；網頁上傳端點（Q-014 已決定第一版不做）；手機經 iCloud 存檔（待實測）；跨庫統一搜尋（Q-012）；Podcast／頻道自動追蹤。

## PO 使用流程（三句話）

1. 要逐字稿 prompt → 問 agent「給我逐字稿 prompt」，貼進 Google AI Studio，輸出存成檔案放進資料匣。
2. 對 agent 說「匯入」→ agent 逐檔回報結果，並提出摘要草稿與下一步提示。
3. 對摘要說「同意」→ 摘要才入庫。
其餘（查詢、更正、刪除）皆用平常說話方式，agent 依專案指示處理；討論投資時 agent 自動先搜尋，PO 不需下指令。

## Functional Requirements

- FR-001 系統必須提供獨立的外部內容庫，儲存 YouTube、Podcast、文章三類來源的全文。
- FR-002 每筆必填：來源類型、連結、標題、頻道／作者、日期（Q-006）。收件匣檔案開頭須有包含這五項的中繼資料區塊；缺任一項，該檔不入庫並指出缺哪個欄位，不影響同批其他檔案。
- FR-003 每筆在所有查詢輸出中必須附「作者個人觀點，未經查證」標註，不可由呼叫端省略；此標註由系統加上，不要求寫在檔案裡。
- FR-004 收件匣進件：PO 說「匯入」時，系統讀取資料匣中尚未處理的檔案並入庫，全文不經模型輸出；每個檔案各自處理（單檔全有或全無），逐檔回報「成功／重複／失敗與原因」。已處理的檔案不得被誤當新檔再次匯入。
- FR-005 claude.ai 直接收全文（短文備援）：系統接收連結、中繼資料與全文並入庫；工具說明必須標明此路徑會耗輸出 token；此備援 PO 2026-11-25 接受。
- FR-006 兩種進件方式必須套用完全相同的必填檢查、去重與標註規則（共用核心）。
- FR-007 單一來源入庫為「全有或全無」：任何一步失敗，庫內不得留下該筆的部分內容。
- FR-008 全文檢索：2 字中文詞必須可查到；結果列出來源資訊與命中片段，不回整份全文。
- FR-009 取單筆時可指定段落範圍；未指定時回傳全文；一律附完整中繼資料與標註。查詢時亦可取得該筆「已確認摘要」，使 agent 可先看摘要、再取需要的原文片段。
- FR-010 去重（Q-003，PO 已同意）：以來源身分判斷（YouTube 為平台＋影片 ID；Podcast 優先 RSS guid；追蹤碼、時間點等網址參數不影響身分）。YouTube 各種連結寫法（youtu.be、watch?v=、shorts、live、手機版）視為同一影片。重複時不新增，回報既有那筆並詢問是否用新內容取代全文；取代時保留既有已確認摘要。全文雜湊相同但來源不同只警告不擋。匯入時系統只讀取檔案開頭的中繼資料區塊判斷來源是否已存在，已存在者不處理全文，以節省 token。
- FR-011 摘要／觀點歸納與全文分開存放；僅在 PO 明確同意後才以「已確認」狀態入庫；查詢時可區分「全文」與「已確認摘要」（Q-005）。
- FR-012 任何入口都不得在 PO 未確認時寫入摘要；唯讀連接器不得有任何寫入工具。
- FR-013 更新全文（以重新匯入同一來源並確認取代的方式，此做法 PO 2026-11-25 接受）與刪除單筆；刪除須 PO 明確確認，僅在非唯讀端提供（Q-013）。
- FR-014 查詢工具在台股與美股兩個連接器都提供並納入唯讀端；匯入、更新、刪除、確認摘要只在非唯讀端（claude.ai 連接器與本機 Claude Code 的完整 MCP；唯讀端如 Cline 不提供）；須同步唯讀白名單與工具數守門測試（Q-009）。
- FR-015 MVP 要求每筆有連結（檔案中繼資料區塊的連結為必填）；無連結來源不在 MVP，匯入時擋下並指出缺連結（Q-004，PO 2026-11-25 同意）。
- FR-016 專案指示須包含：討論投資時先搜尋外部內容庫；PO 三句話使用說明；Google AI Studio prompt 範本（PO 說「給我逐字稿 prompt」時 agent 能提供）。agent 的遵循度以實際對話驗證，不視為系統保證（Q-020、Q-021）。
- FR-017 每次匯入完成，agent 回報結果時附「下一步」提示（PO 2026-11-25 接受），並逐檔主動提出摘要草稿供 PO 確認（草稿不入庫）；一次匯入多檔時，草稿逐檔提出、逐檔確認。

## Acceptance Scenarios

1. **收件匣匯入 EP466**：PO 用 prompt 產出檔案放進資料匣，說「匯入」→ 庫內新增一筆、可用關鍵字查到、結果帶標註；agent 輸出中沒有出現整份逐字稿。
2. **短文備援**：PO 在 claude.ai 貼連結＋短文＋中繼資料 → 同樣新增一筆，規則與場景 1 相同。
3. **重複連結**：同一影片以不同寫法連結（youtu.be 與 watch?v=，其一帶 si= 與 t=）再匯入 → 不新增第二筆，回報既有那筆並詢問是否取代全文；選擇取代後，已確認摘要仍在。
4. **摘要確認**：匯入後 agent 提出摘要草稿 → PO 未同意前庫內無該摘要；同意後才存入並標「已確認」；拒絕或沉默則庫內仍無摘要。
5. **2 字詞檢索**：搜尋「財測」之類 2 字詞，若全文含有，必須命中並回傳片段與來源資訊；台股與美股兩個連接器都能查到。
6. **缺必填欄位**：檔案開頭缺「頻道／作者」→ 該檔不入庫並指出缺的欄位；同一批其他合格檔案正常入庫。
7. **唯讀端**：以唯讀連接器查詢可成功；匯入、更新、刪除、確認摘要的工具必須不存在或被拒絕。
8. **刪除**：PO 說「刪掉那支影片」→ agent 先確認是哪一筆，PO 明確確認後才刪。
9. **討論時自動引用**：在已更新專案指示的 claude.ai AlphaVibe 專案中，PO 談到庫內有的主題，agent 先搜尋並引用，附來源與標註（以實測對話驗證）。
10. **分段取用**：PO 要求查某段內容 → agent 以搜尋片段定位，只取需要的段落範圍，不整份讀入。

## Success Criteria

- EP466 完成「存檔→匯入→檢索→引用」，且匯入過程 agent 的輸出不含逐字稿。
- 抽測 5 個 2 字中文詞（取自 EP466 內文），每個都能命中。
- 所有查詢輸出 100% 帶「作者個人觀點，未經查證」標註（以測試逐項斷言）。
- 3 種連結寫法重複匯入同一影片，庫內只有 1 筆。
- 未確認的摘要寫入次數為 0（測試覆蓋：兩種進件＋唯讀端）。
- 既有 010／011／評論庫與台美連接器既有測試全數維持通過（不被本功能破壞）。
- PO 實際用三句話流程完成一次完整使用，不需要查文件（PO 驗收）。

## Constraints And Assumptions

- 必須獨立於 alphavibe.db、articles.db、substack.db、us_stocks.db（PO 決定）。
- 資料匣固定為 `poc/data/inbox/`（Q-019）；該路徑已被 `.gitignore` 排除，第三方逐字稿不進 git（2026-11-25 以 git check-ignore 實查）。
- 查詢介面沿用定錨文章的 search／get 慣例；唯讀端以白名單限制寫入（既有慣例）。
- claude.ai 只能呼叫 MCP 工具、不能讀寫 PO 本機檔案（推論，SRC-003）；ngrok／claude.ai 單次工具呼叫大小上限**尚未查到**，只影響短文備援，須在 plan 階段實測（Q-018）。
- 系統無法判斷逐字稿是否完整（例如 AI Studio 長文被截斷）；PO 存檔後自行檢查結尾（見 prompt 提醒）。
- 手機（iCloud）存檔不在 MVP；macOS 隱私權限是否允許服務讀 iCloud 未驗證。
- 檔案開頭中繼資料格式為草稿，可能於 plan 階段微調，屆時需同步更新 prompt 範本。
- 假設：內容僅供 PO 個人使用；系統不提供對外公開、分享或匯出功能（Q-011）。
- 假設：PO 自行用 Google AI Studio 產出逐字稿；系統不負責產生逐字稿。

## Dependencies

- 既有 MCP 伺服器與唯讀包裝、台美兩個 claude.ai 連接器（工具數守門測試需更新）。
- 專案指示 `ALPHAVIBE_CONTEXT.md` 需更新並由 PO 貼進 claude.ai 專案。

| 檔案不可讀／編碼錯誤 | 該檔不入庫，其他檔照常 | 指出哪個檔案、哪種問題 | PO 修正後重放 | No |

```
PO 問 agent 要 prompt ─▶ Google AI Studio 產出逐字稿檔 ─▶ 存入 poc/data/inbox/
                                                              │
PO 說「匯入」（claude.ai 或本機 Claude Code）─────────────────┤   [短文備援] claude.ai 直接貼全文 ─┐
                                                              ▼                                    │
                              共用匯入核心（逐檔）：必填檢查 ─▶ 身分判斷（去重）◀─────────────────┘
                                     │                              │
                         失敗：該檔不入庫、其他檔照常      已存在：回報既有並問是否取代（Q-003）
                                                              │
                                              新來源：全文入庫（標註固定附上）
                                                              │
                      agent 提出摘要草稿 ─▶ PO 明確同意？ ──是─▶ 摘要以「已確認」入庫
                                                       └─否／沉默─▶ 不入庫
查詢（台股／美股連接器，含唯讀端）：討論投資時 agent 先 search（片段＋來源＋標註）─▶ 需要時 get（可指定段落）
```

## 狀態模型

- 內容：`已入庫`（可查）→ `全文已更新`（仍為已入庫）→ `已刪除`（需 PO 明確確認，不可查）。
- 摘要（每筆內容可有 0..n 則）：`草稿（僅存在對話中，不入庫）` → PO 同意 → `已確認（入庫、可查）`；PO 拒絕或沉默 → 不存在於庫。
- 資料匣檔案：`待處理` → `已處理`（入庫成功，或 PO 對重複選擇「放棄」後）；失敗者與「重複且 PO 尚未決定」者維持待處理；PO 選擇「取代全文」後該檔入庫並轉為已處理。
- 不允許的轉移：任何路徑把摘要直接寫成「已確認」而無 PO 明確同意。
- 撤回／修改已確認摘要：可撤回與修改，修改視同重新確認須 PO 同意，僅非唯讀端（Q-017，細節留 plan）。

## Data Lifecycle And Security Notes

- 資料：每筆含來源類型、連結、標題、頻道／作者、日期、全文、入庫時間、（可選）已確認摘要；全文雜湊用於提示同內容重複。
- 保存期限：無自動過期；刪除僅由 PO 明確指示。
- 與評論庫既有資料無遷移；Q-015 為獨立決定。
- 存取：沿用既有連接器密鑰路徑保護；系統只讀取 `poc/data/inbox/` 內的檔案，不得讀取該資料夾以外的路徑。
- 稽核：入庫、更新、刪除、摘要確認都要有可追的紀錄（何時／哪一筆），細節留 plan。
