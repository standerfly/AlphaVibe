# Spec Kit Input: 定錨產業筆記文章自動匯入

**Status:** Draft
**Source Product Spec:** ../../product-spec.md
**Source Scope Decision:** ../../scope-decision.md
**Spec Feature Slug:** investanchors-article-import
**Handoff Order:** 1

## Feature Summary

系統代使用者登入「定錨產業筆記」會員網站（investanchors.com），以低頻、分批的方式取得「台股」「美股」「週報」三類文章的全文與圖片，存入獨立文章庫；使用者可在 claude.ai／Claude Code 對話中搜尋與讀取文章（含表格圖中的數字），與 LLM 討論。

## Actors

- 使用者（訂閱者本人，唯一使用者）：搜尋、閱讀、與 LLM 討論文章。
- 排程：代使用者登入並取文。

## Problem and Goal

定錨內容只能登入網站後閱讀，目前只能手動複製貼上進知識庫。目標是自動取得並可檢索，且不危及會員帳號。

## In Scope

- 以使用者帳號（email＋密碼，無 captcha）自動登入；每次執行完即登出。
- 取得台股、美股、週報三類文章：標題、發布日期、分類、網址、全文、內文圖片。
- 歷史文章全量回補（分批、可中斷續跑）。
- 新文章以 Gmail 通知信觸發（唯讀檢查寄件者 `postmaster@mailer.investanchors.com`，信內只有標題＋連結）；無新信不登入網站；每週一次清單核對補漏。
- 以文章 ID／網址為唯一身分防重複；略過標題以「【公告】」開頭的置頂公告。
- 表格圖片（財測 EPS、本益比等）於匯入時機器轉寫成文字並存檔、可檢索；轉寫需標示並可回查原圖；採成本最低且抽查合格的模型。
- 兩個唯讀查詢能力：關鍵字搜尋文章、讀取單篇全文。台股連接器可見台股＋週報，美股連接器可見美股，互不可見。
- 新文章 Telegram 通知（標題＋連結）；失敗 Telegram 通知。

## Out of Scope

- 自動抽取個股立場或寫入個股立場庫；自動摘要。
- 「產業」「總經」「最愛」分類；文章留言。
- STND 網頁閱讀頁。
- 表格數字逐格結構化為可計算欄位。
- 對外分享或再發布內容。

## User Scenarios

1. 首次回補：分多批、歷時數天取得三類全部歷史文章，完成後與網站清單逐篇核對無缺漏。
2. 重跑：新增 0 篇、無重複。
3. 新文章：網站新增文章後，下次執行取得該篇並通知使用者標題與連結。
4. 置頂公告不匯入。
5. 搜尋個股名稱可得相關文章與原文連結。
6. 詢問含財測表文章中的某檔個股財測 EPS，LLM 取得的資料含該表格內容，且可回查原圖。
7. 美股連接器搜尋不到台股／週報文章，反之亦然。
8. 密碼錯誤：當次中止、既有文章不變、使用者收到通知。
9. 被擋或連續逾時：中止並拉長下次間隔、通知使用者，不反覆重試。
10. 每次執行結束後網站端不留排程的登入狀態。
11. Gmail 沒有定錨新信的日子不登入網站。
12. 沒有通知信的文章在每週核對時被發現並匯入。
13. 抓取失敗的文章同次不重試，下次排程才試，累計達上限後停止並通知。
14. 以表格內才有的數字或個股代碼搜尋，可找到該文章。

## Functional Requirements

- FR-001 自動登入；帳密不出現在版本庫、對話或日誌。
- FR-002 取得三類文章的標題、日期、分類、網址、全文、內文圖片。
- FR-003 以文章 ID／網址為唯一身分；重複執行不產生重複紀錄；分類標籤可累加。
- FR-004 置頂公告不匯入。
- FR-005 歷史回補以小批次進行，每批有上限，中斷後從未完成處續跑。
- FR-006 新文章以 Gmail 通知信觸發；無新信不登入網站；每週一次清單核對補漏。
- FR-007 全文可關鍵字檢索，結果可回溯原文網址與日期。
- FR-008 登入失敗、被阻擋、頁面結構改變時中止當次、不刪既有資料、通知使用者。
- FR-009 不改變使用者在網站上的資料（不留言、不按最愛、不改設定）；文章變為「已讀」為可接受的例外。
- FR-010 內容僅供使用者個人使用，不得經無驗證的公開網址提供。
- FR-011 每次執行完即登出、不常駐登入狀態、避開使用者常用時段，使帳號不超過網站「最多兩台裝置或瀏覽器上線」的限制。
- FR-012 對話中可搜尋與讀取文章；台美連接器分流。
- FR-013 表格圖片於匯入時機器轉寫成文字並存檔，可檢索、可在討論時取得；轉寫須標示、可回查原圖；轉寫失敗不得以空白或猜測值充數，須標記「未轉寫」並可事後補轉（不需重抓網站）。
- FR-014 新文章以 Telegram 通知，僅標題與連結。
- FR-015 低頻為硬性要求：每次篇數、每日次數、篇間隔皆有保守上限。
- FR-016 表格轉寫採成本最低且準確度合格的模型；上線前以真實表格抽查，不合格則升級。
- FR-017 失敗文章同次不重試、下次排程再試、累計達上限即停止並通知；被擋跡象出現時整次中止並拉長下次間隔。

## Success Criteria

- 回補後與網站三類清單逐篇核對無缺漏、無重複。
- 連續兩週無重複、無遺漏新文章；無新信的日子網站登入次數為 0。
- 所有失敗情境皆有通知且既有資料不損。
- 帳號未被鎖、停用或限制存取。
- 抽查含表格的文章，表格數字可在對話中取得且與原圖一致，不一致者有標示。

## Constraints and Assumptions

- 網站條款：允許個人使用目的之瀏覽及下載；禁止散布與公開發表；同一帳號最多兩台裝置或瀏覽器上線，超過可停用帳號；有「不得進行不利於本網站的行為」條款。
- 低頻上限建議起始值：每次最多 5 篇、每日最多 2 次、篇間隔 30～90 秒隨機；可更保守，放寬須使用者同意。
- 清單上的日期與紅色數字不可靠（置頂公告日期在未來；數字可能是未讀數）；新舊與完整性只靠文章 ID 與逐篇核對。
- Gmail 唯讀取信沿用專案既有機制；表格轉寫需讀圖模型 API 金鑰（存鑰匙圈），會產生少量費用。
- 單篇失敗重試上限建議 3 次；被擋後下次執行至少延後一天。
- 排程在使用者的 Mac 上執行；帳密存於 macOS 鑰匙圈；登入狀態檔視同密碼。
- 文章無附件或 PDF；內文為文字段落加表格圖片。
- 台股與美股為獨立系統，文章庫獨立於兩者既有資料庫。
- 待技術規劃第一步在 Mac 探查：清單是否分頁、文章網址形態、`lv=` 參數意義、登入狀態有效期、分類是否互斥、開啟文章是否改變已讀。

## Source Decisions

- 範圍／回補／先存全文：Q-001～Q-003。已讀可接受：Q-004。獨立文章庫＋查詢工具：Q-005。多標籤保險：Q-006。表格數字進 MVP：Q-007。個人使用＋低頻：Q-008。公告略過：Q-009。跑完登出：Q-011。新文章通知：Q-012。探查項：Q-013。Gmail 觸發：Q-014。ID 記帳與重試間隔：Q-015。匯入時轉寫與模型選擇：Q-016。
