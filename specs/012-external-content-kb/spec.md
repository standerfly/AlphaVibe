**Feature Branch**: `012-external-content-kb`  
**Created**: 2026-11-25  
**Status**: Draft  
**Input**: User description: "docs/spec-intake/external-content-kb/spec-kit-inputs/external-content-kb/speckit-input.md（已 Accepted 的輸入包）"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 把一支影片或一集 Podcast 存進知識庫（Priority: P1）

PO 看到一支有參考價值的 YouTube 影片（或 Podcast、文章），把來源連結貼給 agent 並請它建立匯入檔。
agent 先確認庫裡有沒有這個來源；沒有的話，在固定的收件資料匣建好一個檔案——標題、頻道或作者、日期、連結已填好，內文留白——
並告訴 PO 檔案位置。PO 開檔把逐字稿貼進內文、存檔，然後說「匯入」，系統讀檔入庫，agent 回報結果。
逐字稿全程不經過 agent 的輸出。

**Why this priority**: 沒有內容進得來，其他功能都沒有意義；也是 PO 日常最頻繁的操作，且要求「不耗 token、約三步完成」。

**Independent Test**: 以 PO 的首個實例逐字稿（Podcast「股市隱者」第 466 集，簡稱 EP466）走完「建檔→貼入→匯入」，
確認庫內新增一筆、可用關鍵字查到、查詢結果帶「作者個人觀點，未經查證」標註，且 agent 的輸出中沒有出現整份逐字稿。

**Acceptance Scenarios**:

1. **Given** 庫裡沒有某支影片，**When** PO 貼該影片連結請 agent 建檔，**Then** 資料匣出現中繼資料已填好、內文空白的檔案，agent 回報檔案位置。
2. **Given** 檔案內文已貼入並存檔，**When** PO 說「匯入」，**Then** 該檔入庫、agent 逐檔回報「成功」，並附下一步提示與摘要草稿。
3. **Given** agent 無法取得標題、頻道或日期，**When** 建檔時，**Then** agent 向 PO 詢問缺的欄位，不得猜測填入。
4. **Given** 檔案內文為空白，**When** PO 說「匯入」，**Then** 該檔不入庫並明確指出「內文為空」。
5. **Given** 一次放了多個檔案、其中一個缺必填欄位，**When** PO 說「匯入」，**Then** 缺欄位的檔案被擋下並指出缺哪個欄位，其餘合格檔案照常入庫。
6. **Given** PO 用 AI Studio 產出了含中繼資料區塊的完整檔案並放進資料匣，**When** PO 說「匯入」，**Then** 同樣入庫，規則與建檔流程完全一致。

### User Story 2 - 討論投資時自動查詢並引用（Priority: P1）

PO 在 claude.ai 的 AlphaVibe 專案（或本機 Claude Code）討論投資時，agent 先搜尋外部內容庫；
搜尋結果顯示命中片段與來源資訊，必要時只取需要的段落全文，引用時一律附上「作者個人觀點，未經查證」。
PO 不需要下指令，台股與美股兩個連接器都查得到同一批內容。

**Why this priority**: 這是整個功能存在的目的——把外部內容變成討論時可回溯、可引用的知識；與匯入同為 MVP 必要。

**Independent Test**: 在庫內已有 EP466 的前提下，在專案中談到該集內容的主題，確認 agent 主動搜尋、引用並附來源與標註；
另以 5 個取自 EP466 內文的 2 字中文詞逐一搜尋，確認都能命中。

**Acceptance Scenarios**:

1. **Given** 庫內有某筆內容，**When** PO 搜尋其中出現的 2 字中文詞（例如「財測」），**Then** 必須命中並回傳命中片段與來源資訊，不得因詞太短而回空。
2. **Given** 搜尋命中多筆，**When** 回傳結果，**Then** 只含命中片段與來源，不回整份全文。
3. **Given** PO 要看某段內容，**When** 指定段落範圍取用，**Then** 只回該段，不整份讀入。
4. **Given** 一筆內容已有 PO 確認過的摘要，**When** agent 查詢該筆，**Then** 可取得摘要並與原文區分，使 agent 先看摘要、不足再取原文片段。
5. **Given** 同一關鍵字，**When** 分別在台股與美股連接器查詢，**Then** 兩邊都查得到該筆內容。
6. **Given** 任何查詢輸出，**When** 回傳內容，**Then** 一律附「作者個人觀點，未經查證」標註，呼叫端不可省略。

### User Story 3 - 摘要必須經 PO 同意才入庫（Priority: P2）

內容入庫後，agent 提出摘要或觀點歸納草稿。草稿只存在對話中；PO 明確說「同意」，摘要才以「已確認」入庫，
之後查詢時可與原文區分。PO 拒絕、要求修改或沒有回應，庫內都不會出現該摘要。

**Why this priority**: 是 PO 明確要求的底線（不可自動寫入摘要），但沒有它，P1 兩個故事仍可獨立運作。

**Independent Test**: 匯入一筆內容後取得摘要草稿，分別測試「同意／拒絕／沉默」三種回應，確認只有「同意」會讓摘要出現在庫內。

**Acceptance Scenarios**:

1. **Given** agent 提出摘要草稿，**When** PO 尚未同意，**Then** 庫內沒有該摘要。
2. **Given** 摘要草稿，**When** PO 明確同意，**Then** 摘要以「已確認」入庫並可被查詢。
3. **Given** 摘要草稿，**When** PO 拒絕或沒有回應，**Then** 庫內仍沒有該摘要。
4. **Given** 一次匯入多個檔案，**When** agent 提出摘要，**Then** 草稿逐檔提出、逐檔確認，不合併確認。
5. **Given** 任何進件方式或唯讀端，**When** 嘗試在 PO 未確認時寫入摘要，**Then** 一律被拒絕。

---

### User Story 4 - 重複來源與更新全文（Priority: P2）

PO 忘了已存過某支影片，又貼了一次（連結寫法可能不同，例如短網址、帶追蹤碼或時間點）。
系統辨識為同一來源，不新增第二筆，告訴 PO 已存在，並詢問是否要用新內容取代全文；取代時，已確認的摘要保留。

**Why this priority**: 避免庫內累積重複內容、也讓 PO 能修正逐字稿錯字；不影響 P1 的基本流程。

**Independent Test**: 以三種寫法的連結重複匯入同一支影片，確認庫內只有 1 筆，且選擇取代全文後已確認摘要仍在。

**Acceptance Scenarios**:

1. **Given** 庫內已有某影片，**When** PO 以另一種連結寫法再匯入，**Then** 不新增，回報既有那筆並詢問是否取代全文。
2. **Given** PO 選擇取代全文，**When** 取代完成，**Then** 全文為新內容、既有已確認摘要保留。
3. **Given** PO 選擇放棄，**When** 回應後，**Then** 庫內不變，該檔視為已處理。
4. **Given** 建檔階段，**When** PO 貼的連結庫內已有，**Then** 不建檔並告知既有那筆。
5. **Given** 兩個不同連結但全文內容相同，**When** 匯入，**Then** 只警告「可能重複」，不阻擋。
6. **Given** 已入庫的檔案仍留在資料匣，**When** PO 再說「匯入」，**Then** 不得重複入庫，回報「已處理」。

---

### User Story 5 - 刪除與撤回（Priority: P3）

PO 想刪除某筆內容，或撤回、修改已確認的摘要。刪除與修改都要 PO 明確確認；
修改摘要視同重新確認。

**Why this priority**: 是完整性需求，但日常使用頻率低。

**Independent Test**: 要求刪除一筆內容，確認 agent 先確認是哪一筆、PO 明確確認後才刪；撤回一則已確認摘要後確認查詢不再出現。

**Acceptance Scenarios**:

1. **Given** PO 說「刪掉那支影片」，**When** agent 處理，**Then** 先確認是哪一筆，PO 明確確認後才刪除。
2. **Given** PO 未確認，**When** 結束對話，**Then** 沒有任何內容被刪除。
3. **Given** 一則已確認摘要，**When** PO 要求修改，**Then** 修改須 PO 同意，視同重新確認。
4. **Given** 一則已確認摘要，**When** PO 要求撤回，**Then** 該摘要不再被查詢到。

---

### User Story 6 - 唯讀端安全與短文備援（Priority: P3）

只需查詢的情境（例如自動化工具的查詢）只能讀、不能寫：匯入、建檔、更新、刪除、確認摘要的功能完全不存在。
另外，PO 在 claude.ai 直接貼少量文字也能入庫作為備援，但須讓 PO 知道這條路徑會耗較多 token。

**Why this priority**: 唯讀限制是安全底線；短文備援是便利功能，兩者都不影響主流程。

**Independent Test**: 以唯讀端嘗試所有寫入類操作確認皆不可用；以一段短文走備援路徑確認入庫規則與主流程一致。

**Acceptance Scenarios**:

1. **Given** 唯讀端，**When** 嘗試匯入、建檔、更新、刪除或確認摘要，**Then** 該功能不存在或被明確拒絕。
2. **Given** claude.ai 直接貼短文＋連結＋中繼資料，**When** 入庫，**Then** 套用與主流程完全相同的必填檢查、去重與標註。
3. **Given** 短文超過傳輸上限，**When** 送出，**Then** 不入庫、不留半筆，回報「內容過長」並建議改走資料匣。

---

### Edge Cases

- 資料匣不存在或沒有待處理檔案時說「匯入」：回報「資料匣沒有待匯入檔案」，不入庫。
- 檔案不可讀或編碼錯誤：該檔不入庫並指出哪個檔案、哪種問題，其他檔照常。
- 中繼資料區塊格式錯誤（無法解析）：該檔不入庫並指出問題，其他檔照常。
- 連結無法判斷平台或影片：該檔不入庫並說明原因。
- 建檔時 agent 取不到標題、頻道或日期：詢問 PO，不猜測。
- 建檔工具無法在資料匣寫入檔案：不建檔並回報原因。
- 入庫中途失敗：單筆全有或全無，庫內不留殘留；重送不得造成重複。
- 逐字稿長文在 AI Studio 被截斷：系統無法判斷是否完整，由 PO 存檔後自行檢查結尾。
- 重複且 PO 尚未決定時：該檔維持待處理，不入庫也不丟棄。
- agent 在討論時沒有主動搜尋：屬遵循度問題，PO 可直接要求「查外部內容庫」，必要時調整專案指示。
- 摘要未經 PO 確認就被要求入庫：拒絕，並說明須 PO 明確同意。
- 同一集 Podcast 同時有 YouTube 版與 RSS 版：不自動合併，僅以內容相同警告。
- 同一影片的各種連結寫法（短網址、完整網址、短影片、直播、手機版，帶追蹤碼或時間點）：視為同一影片。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 提供獨立的外部內容庫，儲存 YouTube、Podcast、文章三類來源的全文，且與既有的評論、定錨文章、Substack、美股資料庫分開。
- **FR-002**: System MUST 要求每筆內容有來源類型、連結、標題、頻道或作者、日期；資料匣檔案開頭須有含這五項的中繼資料區塊；缺任一項或區塊格式錯誤，該檔不入庫並指出缺哪個欄位或哪裡格式錯誤，不影響同批其他檔案；內文為空白的檔案不入庫並指出「內文為空」。
- **FR-003**: System MUST 在所有查詢輸出中為每筆內容附「作者個人觀點，未經查證」標註，呼叫端不可省略；標註由系統加上，不要求寫在檔案裡。
- **FR-004**: System MUST 在 PO 說「匯入」時讀取資料匣中尚未處理的檔案並入庫，全文不經過 agent 輸出；每個檔案各自處理（單檔全有或全無），逐檔回報「成功／重複／失敗與原因」；已處理的檔案不得被誤當新檔再次匯入。
- **FR-005**: System MUST 提供 claude.ai 直接收全文的短文備援，並在工具說明中標明此路徑耗輸出 token。
- **FR-006**: System MUST 對所有進件方式套用完全相同的必填檢查、去重與標註規則。
- **FR-007**: System MUST 使單一來源的入庫全有或全無：任何一步失敗，庫內不得留下該筆的部分內容。
- **FR-008**: System MUST 支援全文檢索，2 字中文詞必須可查到；結果列出來源資訊與命中片段，不回整份全文。
- **FR-009**: System MUST 允許取單筆內容時指定段落範圍，未指定則回傳全文，一律附完整中繼資料與標註；並可取得該筆的已確認摘要。
- **FR-010**: System MUST 以來源身分判斷重複：YouTube 以平台加影片身分、Podcast 優先以其發布來源提供的唯一識別；追蹤碼、時間點等網址參數不影響身分；短網址、完整網址、短影片、直播、手機版視為同一影片。重複時不新增，回報既有那筆並詢問是否用新內容取代全文；取代時保留既有已確認摘要；全文雜湊相同但來源不同只警告不阻擋；匯入時只讀檔案開頭中繼資料區塊判斷來源是否已存在，已存在者不處理全文。
- **FR-011**: System MUST 將摘要與全文分開存放；僅在 PO 明確同意後才以「已確認」狀態入庫；查詢時可區分「全文」與「已確認摘要」；已確認摘要可撤回與修改（僅非唯讀端），修改視同重新確認須 PO 同意。
- **FR-012**: System MUST 確保任何入口都不得在 PO 未確認時寫入摘要；唯讀端不得有任何寫入類功能。
- **FR-013**: System MUST 支援更新全文（重新匯入同一來源並確認取代）與刪除單筆；刪除須 PO 明確確認，僅非唯讀端提供。
- **FR-014**: System MUST 在台股與美股兩個連接器都提供查詢並納入唯讀端；匯入、建立待匯入檔案、更新、刪除、確認摘要只在非唯讀端提供；既有唯讀限制機制與相關測試須同步更新。
- **FR-015**: System MUST 要求每筆有連結；無連結的檔案匯入時被擋下並指出缺連結。
- **FR-016**: System MUST 讓專案指示包含：建立匯入檔的說法與流程；討論投資時先搜尋外部內容庫；三步使用說明；AI Studio 逐字稿 prompt 範本。agent 遵循度以實際對話驗證，不視為系統保證。
- **FR-017**: System MUST 在每次匯入完成後，由 agent 回報結果時附「下一步」提示，並逐檔主動提出摘要草稿供 PO 確認（草稿不入庫）；多檔時逐檔提出、逐檔確認。
- **FR-018**: System MUST 支援建立待匯入檔案：PO 提供連結（及 agent 取不到的中繼資料）後，先判斷來源是否已存在（規則同 FR-010）；已存在則告知既有那筆、不建檔；不存在則在資料匣建立檔案，中繼資料區塊已填妥、內文空白，並回報路徑；標題、頻道或作者、日期無法取得時由 agent 詢問 PO，不得猜測填入；由服務端工具實際建檔；唯讀端不提供此功能。
- **FR-019**: System MUST 只讀取資料匣內的檔案，不得讀取該資料夾以外的路徑。
- **FR-020**: System MUST 對入庫、更新、刪除、摘要確認留下可追的紀錄（何時、哪一筆）。
- **FR-021**: System MUST 為每筆保存來源類型、連結、標題、頻道或作者、日期、全文、入庫時間、（可選）已確認摘要，並另存全文雜湊用於提示同內容重複；無自動過期，刪除僅由 PO 明確指示。

### Key Entities

- **外部內容（Content）**：一筆被納入的來源；屬性含來源類型（YouTube／Podcast／文章）、連結、標題、頻道或作者、日期、全文、入庫時間、全文雜湊；以來源身分唯一。
- **已確認摘要（Confirmed Summary）**：附屬於某筆內容、經 PO 明確同意才存在的摘要或觀點歸納；一筆內容可有零到多則；可撤回、修改。
- **資料匣檔案（Inbox File）**：放在固定資料匣的待匯入檔案；含中繼資料區塊與內文；狀態為「待填寫（內文空白）」「待處理」「已處理」。待填寫→待處理由系統在匯入時依內文是否為空判斷；入庫成功、或 PO 對重複選擇放棄後為已處理；入庫失敗、或重複且 PO 尚未決定者維持待處理。
- **稽核紀錄（Audit Record）**：記錄入庫、更新、刪除、摘要確認發生的時間與對象。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: EP466 完成「建檔→貼入→匯入→檢索→引用」全流程，且匯入過程 agent 的輸出不含逐字稿。
- **SC-002**: 抽測 5 個取自 EP466 內文的 2 字中文詞，5 個全部能命中。
- **SC-003**: 所有查詢輸出 100% 帶「作者個人觀點，未經查證」標註（以逐項測試斷言）。
- **SC-004**: 以 3 種連結寫法重複匯入同一影片，庫內只有 1 筆。
- **SC-005**: 在各種進件方式與唯讀端下，未經 PO 同意的摘要寫入次數為 0。
- **SC-006**: 既有定錨文章庫、Substack 庫、評論庫與台美連接器的既有測試全數維持通過。
- **SC-007**: PO 實際用「貼連結請建檔→貼內文並匯入→對摘要說同意」三步完成一次完整使用，不需要查文件。

## Assumptions

- PO 是唯一使用者，內容僅供個人使用；系統不提供對外公開、分享或匯出功能。
- PO 自行用 Google AI Studio 產出逐字稿；系統不負責產生逐字稿。
- 資料匣固定為 `poc/data/inbox/`，該路徑已被版本控制排除，第三方逐字稿不進版本庫。
- 手機經 iCloud 存檔不在第一版；建檔需在 PO 的 Mac 上開檔貼入內文。
- agent 能否自動取得 YouTube 標題、頻道、日期尚未驗證；取不到時詢問 PO。
- claude.ai 本身不能建立 PO Mac 上的檔案；claude.ai 單次工具呼叫大小上限尚未查到，只影響短文備援，規劃階段實測。
- 系統無法判斷逐字稿是否完整，PO 存檔後自行檢查結尾。
- 檔案開頭中繼資料格式為草稿，規劃階段可微調，須同步更新 AI Studio prompt 範本。
- 規劃階段須確認：建檔工具只能在資料匣內建立檔案；唯讀端不提供建檔；「待填寫」狀態的呈現方式；建檔寫入失敗時的處理。其中「唯讀端不提供建檔」是需求層已採用的邊界（FR-014、FR-018），待確認的只是實作方式。
- 不在範圍（Out of Scope）：評論庫既有資料的刪除或遷移；修改定錨文章庫、Substack 庫、評論庫、美股庫的任何資料表或程式；任何未經 PO 確認的自動摘要寫入；對外公開、分享或匯出。
- 專案指示須由 PO 更新並貼進 claude.ai 專案；連接器沿用既有密鑰路徑保護。
- 不依賴 Substack 抓取功能（其尚未完成）；與既有四個資料庫完全分開，不修改它們。
- 後續（不在第一版）：自動抓字幕與 Whisper 轉錄、網頁上傳端點、手機 iCloud 存檔、跨庫統一搜尋、Podcast 與頻道自動追蹤。
