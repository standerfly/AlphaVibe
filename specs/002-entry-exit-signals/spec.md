## User Scenarios & Testing *(mandatory)*

### User Story 1 - 為持股設定停損停利門檻並被動態監控 (Priority: P1)

PO 與 Claude 討論某檔持股後決定「跌破 X 元要停損」或「漲到 Y 元要停利」，
系統記住這個決定，之後持續比對現價，達到門檻時主動標示出來。沒有設定
門檻的持股要明確顯示「尚未設定」，不能讓 PO 誤以為它是安全的。

**Why this priority**：這是階段B 的核心——階段A 給了損益數字，但數字
本身不會告訴 PO「該動作了」。門檻是把被動查詢變成主動提醒的關鍵。

**Independent Test**：為一檔持股設定門檻後，用高於/低於門檻的現價分別
驗證觸發與未觸發狀態；對未設定門檻的持股驗證回傳「尚未設定」而非
「安全」。

**Acceptance Scenarios**：

1. **Given** PO 與 Claude 討論後為某檔設定停損門檻，
   **When** 該檔現價跌破門檻，
   **Then** 系統標示該檔已觸發停損，並顯示門檻值、現價、觸發幅度。
2. **Given** 某檔持股從未設定過門檻，
   **When** PO 檢視該檔或全部持股，
   **Then** 明確顯示「尚未設定門檻」，**不得**顯示為安全、未觸發或
   任何預設門檻值。
3. **Given** PO 想調整既有門檻，
   **When** 重新設定同一檔的門檻，
   **Then** 系統以新值為準，且保留調整前的值供追溯。

### User Story 2 - 基本面與股價背離時收到提醒 (Priority: P2)

系統偵測「營收年增率轉強但股價沒跟上」或「股價漲但基本面沒跟上」這類
背離，主動提醒 PO。這是 product-spec FR-051 規劃過「利多出盡」但一直
沒實作的部分。

**Why this priority**：背離是進出場時機的重要訊號，但不像門檻那樣有
明確的觸發點，需要 PO 自行判斷，價值略低於 US1。

**Independent Test**：用構造的資料（營收 YoY 上升但股價百分位下降、
以及反向組合）驗證偵測結果；用資料不足的情況驗證回傳「無法判斷」。

**Acceptance Scenarios**：

1. **Given** 某檔近幾期營收年增率持續上升、但現價百分位偏低，
   **When** 系統執行背離偵測，
   **Then** 標示為「基本面轉強但股價未跟上」並附兩邊的數據依據。
2. **Given** 某檔營收年增率或股價歷史任一資料不足，
   **When** 系統執行背離偵測，
   **Then** 回傳「資料不足，無法判斷」，不得單憑一邊的資料下結論。

### User Story 3 - 訊號觸發時一併看到可以怎麼調整 (Priority: P2)

當停損停利或背離訊號觸發時，系統除了說「觸發了」，也一併列出這檔
接下來可以怎麼處理（減碼、換股、續抱的理由等），讓 PO 有決策起點而不是
只有一個警訊。

**Why this priority**：與 US1／US2 同等重要，但技術上依賴它們的訊號輸出，
故排在其後。

**Independent Test**：對已觸發的標的驗證回傳包含具體可選項；對資料不足
以產生建議的情況，驗證訊號本身仍照常顯示、建議欄位標示資料不足。

**Acceptance Scenarios**：

1. **Given** 某檔觸發停利門檻，
   **When** PO 檢視該檔，
   **Then** 除了觸發標示，也看到可選的調整方向與各自的依據。
2. **Given** 訊號觸發但缺乏產生建議所需的資料，
   **When** PO 檢視該檔，
   **Then** 訊號本身仍然顯示（不被吞掉），建議欄位標示「資料不足，
   需人工判斷」。

### User Story 4 - 訊號自動出現，不必主動查詢 (Priority: P3)

訊號在每日既有的自動檢視流程中一併產生，PO 打開頁面就看得到，不需要
記得去問。

**Why this priority**：主動化是價值放大器，但 US1~US3 的訊號本身要先
正確，故列 P3。

**Independent Test**：在測試環境執行一次完整的每日檢視流程，驗證新訊號
與既有檢查結果一起產生並被記錄，且不影響既有檢查項目。

**Acceptance Scenarios**：

1. **Given** 每日自動檢視流程執行，
   **When** 某檔觸發停損或背離訊號，
   **Then** 該訊號與既有檢查結果一併被記錄，PO 在既有的檢視入口就能
   看到，不需要額外操作。
2. **Given** 新訊號的計算失敗或資料異常，
   **When** 每日流程執行，
   **Then** 既有檢查項目不受影響照常完成，失敗的部分標示出來。

---

### User Story 5 - 頁面上的損益數字與工具一致 (Priority: P3)

報告頁面顯示的浮動損益改用階段A 的 FIFO 計算，讓 PO 在頁面看到的數字
與對話中查詢到的一致，不會出現「同一檔兩個數字」。

**Why this priority**：一致性問題，不影響新功能運作，但兩套並存久了會
造成信任問題。

**Independent Test**：對同一檔比對頁面顯示與 `get_position_pnl` 的輸出，
數字須一致；對賣超標的驗證頁面同時顯示「FIFO 無法計算＋原因」與
「標註口徑的加權平均估算值」，且兩者視覺上可區分。

**Acceptance Scenarios**：

1. **Given** 某檔有完整買賣紀錄，
   **When** PO 在頁面檢視其浮動損益，
   **Then** 數字與 `get_position_pnl` 的 FIFO 結果一致。
2. **Given** 某檔的賣出量超過流水表買進量（實測約 1/3 持股如此），
   **When** PO 在頁面檢視，
   **Then** 同時看到「FIFO 無法計算：歷史不完整」的說明，以及標註
   「加權平均估算、未扣賣出、非 FIFO」的既有估算值；兩者視覺上可區分。
   **不得**顯示空白或 0，也**不得**讓估算值看起來像 FIFO 的結果
   （PO 裁決 Q2-C，見 FR-015）。

---

### Edge Cases

- **未設定門檻的持股**：實測 `position_plans` 只有 1 檔有資料，可預期
  門檻初期也是多數未設定——「尚未設定」會是常態而非例外，呈現上不能
  當成錯誤狀態。
- **FIFO 切換的顯示回歸（已由 FR-015 處理）**：實測 60 檔中 21 檔賣超，
  若單純換成 FIFO，這些標的的未實現損益會從「有一個（失真的）數字」
  變成「無法計算」，走勢圖的均價虛線也會消失。PO 裁決 Q2-C 要求兩種
  口徑並存並標註，正是為了避免這個每日可見的退步。
- **自動記錄洗版**：實測立場記錄 474 筆中 **437 筆是每日流程自動寫的**
  （每日新增 11~26 筆），PO 手寫僅 37 筆。新訊號若也自動寫入，會讓
  PO 自己的原始判斷更難被看見。
- **每日流程的時間預算**：實測基準線 39 檔跑 **18.3 分鐘**（約 28 秒/檔），
  主要成本在既有的估值歷史查詢（每檔 38 次外部呼叫）。新增任何「逐檔
  外部查詢」都要按「檔數 × 呼叫次數」計算成本。
- **營收資料的期數上限**：實測既有資料窗口可得 14 筆年增率，超過就需要
  加長窗口。
- **文件與實作不一致**：每日流程實際執行時間是 17:00，但程式碼註解有
  寫 18:00 與 02:00 的——以實際排程設定為準。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**：系統 MUST 提供機制讓 PO 與 Claude 討論後為指定持股記錄
  停損與/或停利門檻，並保留調整前的值供追溯。
- **FR-002**：系統 MUST 持續比對現價與已記錄的門檻，並在達到門檻時
  標示觸發，附門檻值、現價與觸發幅度。
- **FR-003**：未設定門檻的持股 MUST 明確顯示「尚未設定」，MUST NOT
  顯示為安全、未觸發，也 MUST NOT 套用任何未經 PO 設定的預設門檻值。
- **FR-004**：門檻 MUST 可透過對話設定，MUST NOT 在本階段新增網頁
  設定表單（PO 裁決 2026-09-03：Q3 選項 A——門檻的價值在於「討論後」
  才設定，網頁表單會鼓勵不經討論就隨手改）。
  **重要邊界**：設定門檻是寫入操作，因此只能在具備完整工具存取的主
  對話進行；唯讀路徑（Cline 的 `server_readonly` 白名單、`stock-researcher`
  唯讀 subagent）依設計看不到也用不到這個能力。若未來希望在唯讀
  subagent 內也能設定門檻，那是放寬其唯讀邊界的獨立決策，不在本階段。
- **FR-005**：系統 MUST 偵測基本面訊號（營收年增率趨勢）與股價位置
  之間的背離，並在偵測到時標示方向（基本面轉強但股價未跟上／股價漲但
  基本面未跟上）並附兩邊的數據依據。
- **FR-006**：當營收年增率或股價歷史任一資料不足以支撐判斷時，系統
  MUST 回傳「資料不足，無法判斷」，MUST NOT 單憑一邊的資料下結論。
- **FR-007**：系統 MUST 擴大既有營收年增率趨勢判斷的觀察期數（現況
  只看最近 3 期的連續下滑、與最近 2 期的加速比較），以取得更穩定的
  趨勢判斷。此擴大 MUST NOT 增加外部 API 呼叫次數。
- **FR-008**：當停損停利或背離訊號觸發時，系統 MUST 一併提供該檔可以
  怎麼調整的建議選項與依據。範圍限於觸發當下的該檔持股，MUST NOT
  延伸為主動選股或市場掃描。
- **FR-009**：訊號觸發但資料不足以產生建議時，系統 MUST 仍照常顯示
  訊號本身，並在建議欄位標示資料不足；MUST NOT 因為建議產不出來就
  隱藏訊號。
- **FR-010**：新訊號 MUST 併入既有的每日自動檢視流程產生，讓 PO 在
  既有的檢視入口就能看到，不需額外操作。
- **FR-011**：新訊號的計算失敗 MUST NOT 影響既有檢查項目的執行與記錄；
  失敗的部分要標示出來。
- **FR-012**：新訊號併入每日流程後 MUST NOT 顯著增加流程的執行時間
  （基準線：39 檔 18.3 分鐘）。任何逐檔的外部資料查詢都要先量測實際
  呼叫次數，不得從參數語意推論。
- **FR-013**：新訊號 MUST NOT 寫入「立場記錄」，只寫入每日檢視結果
  的記錄通道（PO 裁決 2026-09-03：Q1 選項 A）。
  理由：實測立場記錄 474 筆中 437 筆已是每日流程自動寫入、PO 手寫僅
  37 筆，且每檔顯示的「最新立場」永遠是機器寫的那筆——PO 自己的原始
  判斷已被機器文字埋掉。新訊號不再加劇此現象，讓立場記錄回歸
  「PO 的判斷」語意。
  （既有 437 筆自動寫入造成的洗版是另一個議題，本階段不處理。）
- **FR-014**：報告頁面顯示的浮動損益 MUST 改用階段A 的 FIFO 計算，
  使頁面數字與 `get_position_pnl` 一致。
- **FR-015**：FIFO 無法計算的標的（賣出量超過流水表買進量，實測約
  1/3 持股）在頁面上 MUST 同時提供兩個資訊（PO 裁決 2026-09-03：
  Q2 選項 C）：
  (a) 明確說明 FIFO 無法計算及其原因（歷史不完整）；
  (b) 既有的加權平均估算值，且 MUST 標註其口徑為「加權平均估算、
      未扣賣出、非 FIFO」。
  兩者 MUST 在視覺上可區分，MUST NOT 讓估算值看起來像 FIFO 的結果。
  走勢圖的均價虛線在此情況下 MUST 沿用估算值繼續顯示，並在圖例標註
  同樣的口徑說明——避免 PO 每天在看的頁面上有 1/3 標的突然空白。

### Key Entities

- **停損停利門檻（Exit Threshold）**：某檔的停損價與/或停利價、設定
  時間、設定當下的理由；需保留調整歷史。
- **背離訊號（Divergence Signal）**：方向（基本面強/股價弱 或反向）、
  兩邊的數據依據、判斷所用的期數與樣本。
- **訊號建議（Signal Suggestion）**：觸發訊號時附帶的可選調整方向與
  各自依據。

## Success Criteria *(mandatory)*

- **SC-001**：PO 能透過與 Claude 討論為任一持股設定門檻，設定後不需
  再提醒系統，達到門檻時會自己出現。
- **SC-002**：所有「未設定門檻」「資料不足」「無法計算」的狀態 100%
  明確標示，不出現會被誤讀為安全或正常的呈現。
- **SC-003**：新訊號併入每日流程後，流程執行時間相對基準線（39 檔
  18.3 分鐘）的增幅可被量測並在可接受範圍內。
- **SC-004**：頁面顯示的損益數字與對話查詢的結果 100% 一致。
- **SC-005**：新訊號的任何失敗都不會導致既有檢查項目缺漏。

## Assumptions

- **門檻無全域預設值**：沿用階段A FR-E03「PO 與 Claude 逐檔討論後設定」
  的裁決，不提供「未設定就套用 -15%」這類全域預設——那會讓 PO 沒討論過
  的標的看起來像已經有策略。
- **門檻保留調整歷史**：既有的加碼計畫額度是覆寫式（無歷史），但門檻
  背後有討論脈絡，保留歷史才能回答「當初為什麼設在這裡」。
- **背離偵測沿用階段A 的百分位**：股價那一邊直接用階段A 已完成的
  `get_price_position`，不另立一套價格強弱指標。
- **營收期數擴大不需新資料**：實測既有資料窗口一次取得可算出 14 筆
  年增率且有快取，擴大觀察期數在既有資料內完成。
- **不做自動下單**：沿用整個功能的既有邊界。
- **不做主動選股/策略發現**：沿用 Q-006 的裁決。
- **兩種損益口徑並存是刻意的**：FR-015 的裁決讓 FIFO 與加權平均估算
  同時出現在頁面上。這與 FR-014 想解決的「同一檔兩個數字」表面矛盾，
  實際不衝突——FR-014 要消除的是「沒有標示、無從分辨」的兩個數字，
  FR-015 要求的是「標示清楚口徑」的兩個數字。可分辨才是重點。
- **門檻設定僅限主對話**：唯讀路徑（Cline、stock-researcher subagent）
  依設計無法寫入，PO 需在主對話設定門檻。
