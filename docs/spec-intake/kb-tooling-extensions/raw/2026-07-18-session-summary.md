# 原始素材：2026-07-18 對話 session 中的實際開發歷程

> 說明：這是一份回溯性的原始素材。使用者（Stander）今天第一次開始實際使用
> `poc/kb-mcp` 這個 Phase 1 PoC 知識庫（此前是空的），過程中連續遇到具體
> 困擾，當場請 Claude 開發解決，全部已完成並通過獨立驗收 agent 確認。
> 使用者決定先開發、後補 pre-spec，範圍回溯涵蓋今天全部的 `poc/kb-mcp`
> 擴充。本檔案是 AI 依對話紀錄整理的忠實記錄，供 pre-spec 流程萃取需求用。

## 時間軸與困擾點

### 1. 手機看不到資料

使用者用手機開檢視頁看不到今天存的資料。診斷發現根因是常駐渲染服務
`report_server.py` 沒有在跑（8080 port 無 process 監聽）。使用者說明
這台 Mac Mini 會一直開著，要求維持程序常駐。

**處理**：啟動 `report_server.py`，並建立 macOS launchd 服務
（`com.alphavibe.reportserver`，`RunAtLoad`+`KeepAlive`），確保開機/崩潰
後自動重啟，不依賴這個對話存在。

### 2. 交易紀錄手動一筆一筆存，很耗操作、股票代碼常要重新上網查證

使用者陸續貼了朋友「老芋頭」兩天份的股票交易紀錄（共 22 筆），每次都要
一筆一筆呼叫 `save_comment`；其中多檔股票名稱（奇鼎、政美、環宇KY、新盛力、
光洋科、鈺邦、中美晶、全新等，共 18 檔）不在既有資料裡，必須派 agent 上網
查證股票代碼才能存，耗費大量時間與 token。使用者主動問「這樣操作很耗
token嗎？可以建立工具加速並節省token嗎？」。

**處理**：新增兩個能力：
- 股票代碼快取（`stock_aliases` 表 + `save_stock_alias`/`get_stock_alias`
  工具）：查證過的股票名稱→代碼對應存起來，下次同一檔不用重新查證。
- 批次存入評論（`save_comments_batch` 工具）：一次貼一整批交易/評論，
  不用逐筆呼叫工具；內部重用既有 `save_comment` 邏輯，部分筆數缺必填欄位
  時其餘合法筆數仍要存入，不能整批失敗。

已測試驗證（36→45 個測試全綠，歷次），獨立 agent 驗收通過。

### 3. 檢視頁在手機上很難看

使用者反應「現在的UI很難在手機上看，要優化」。診斷發現兩個具體問題：
(a) Layer 1 哲學模組只顯示「模組名稱＋bytes 數」，看不到實際內容；
(b) 立場/快照/持股三個表格是 8-9 欄的寬表格，手機上要橫向捲動，很難讀。

**處理**：
- 哲學模組改成 `<details>/<summary>` 可展開全文（原生 HTML，無 JS）。
- 表格在窄螢幕（≤640px）用 CSS 改成一張張卡片（`data-label` + 偽元素
  技巧），取代橫向捲動。

已改完並重啟常駐服務驗證生效。

### 4. 分析股票時反覆需要查證資料，可靠度不足

使用者今天分析多檔股票（世芯-KY、旺宏、萬潤、京元電子、旺矽等）時，多次
需要以下資料，但現有 `get_fundamentals` 工具不含這些，只能派 agent 上網
搜尋新聞報導：
- 股價從波段高點的實際回檔幅度（agent 多次警告「股價數字多為新聞報導
  盤中價，非官方收盤價序列，精確度有限」——這是今天資料可靠度最弱的一環）
- 月營收年增率（`get_fundamentals` 只給金額，年增率要自己土法估算）
- 外資買賣超動向（篩選框架的條件之一，每次都查不到只能標「未查得」）
- 股票基本資料/產業分類（股票代碼查證本身，見上面第 2 點）

使用者因此提出核心洞察：「我一直無法做好這個投資系統的原因，是需要用到
的外部查詢工具很多，我想先做好這些工具的後端API」，要求依對話過程中
浮現的需求，提出值得做成查詢 API 的項目。

**討論後排定優先序**（第一層：資料源明確存在；第二層：資料源不確定，
本次不做——法人EPS預估、重大訊息摘要）：

第一層 4 個，本次全部完成：
- `get_stock_info`：股票基本資料/產業分類（FinMind dataset `TaiwanStockInfo`）
- `get_stock_price_history`：股價歷史 OHLC（dataset `TaiwanStockPrice`），
  取代不精確的新聞報導盤中價
- `get_revenue_yoy`：月營收年增率，client 端用「今年當月 vs 去年同月」
  自算（API 本身不提供年增率欄位）
- `get_institutional_trading`：三大法人（含外資）買賣超（dataset
  `TaiwanStockInstitutionalInvestorsBuySell`），外資分類欄位經兩輪
  （實作+獨立驗收）真實 API 呼叫實測確認，非猜測

已測試驗證（45 個測試全綠），獨立 agent 驗收通過，包含對真實 FinMind API
的 smoke test。

## 已知的技術取捨與限制（供 pre-spec 釐清時參考）

- `get_stock_info` 對單一股票代碼可能回傳多筆（FinMind 原始資料本身有
  重複的歷史產業分類記錄），目前不做去重，只在開發報告揭露，README
  未特別註記。
- `get_revenue_yoy` 抓 400 天窗口，實測發現多數月份因去年同月資料不在
  窗口內而回傳 `null`，只有最新月份能算出年增率——這是資料窗口限制，
  若要每月都有年增率需要拉長到 450~500 天。
- 法人 EPS 預估、重大訊息摘要兩項查詢 API，因免費資料源不確定，本輪
  明確排除，未來若要做需要另外評估資料源可行性。
- 這一整批工作都是在既有 `poc/kb-mcp`（Phase 1 PoC）上直接擴充，沿用
  純 Python 標準庫、Python 3.9 相容、無外部依賴的既有架構慣例，沒有
  引入新的技術棧。
