# 整合、失敗行為與可觀測性：機票查詢分頁

**Feature Slug:** flight-search
**Last Updated:** 2026-09-23
**對應 readiness check:** Third-party integration、Security/compliance、
Batch processing 部分失敗、Operationally sensitive behavior

## 1. 外部整合清單

| 整合對象 | 用途 | 存取方式 | 是否必要 |
|---|---|---|---|
| Google Flights | 四段票與接駁票查價 | headless 真實 Chrome 抓取網頁 | **主力，必要** |
| Telegram Bot | 達標通知 | 既有推播基礎設施（美股分頁已用） | 必要（僅通知功能） |
| SerpApi | 查價備援 | HTTP API，需使用者自備 key | 選用，無 key 時功能自動降級 |
| Skyscanner | **僅產生連結供人點閱** | 不抓取 | 選用 |

## 2. 逾時與重試語意

| 情境 | 行為 | 依據 |
|---|---|---|
| 單筆查價逾時（偶發） | 重試 1 次 | 實測偶發失敗率約 6.7% |
| 前一筆已失敗時再逾時 | **不重試** | 被擋時重試必然也失敗，只把軟封鎖偵測從 30 秒拖到 60 秒（研究筆記第 15 節實測） |
| 連續失敗達門檻（3 次） | 判定軟封鎖，**立即中止本批** | 繼續打只會加深封鎖（第 14 節白打 16 次的教訓） |
| 整批逾時 | 終止子程序，保留已落地結果 | — |
| Telegram 推播失敗 | 重試 2 次後放棄，於 UI 標示「通知未送達」 | 不可因通知失敗而重跑掃描 |

**節流參數**：查詢間隔隨機（固定間隔本身就是自動化特徵），速率上限以
滾動小時視窗計算。**目前設定的速率值為保守推估而非已驗證安全值**，
系統顯示時必須標註此性質（CON-09）。

## 3. 部分失敗策略（批次處理核心）

掃描**經常部分完成**，這是常態而非例外：

| 原則 | 說明 |
|---|---|
| 逐筆落地 | 每查完一筆立即持久化，不等整批結束 |
| 可接續 | 下一輪自動跳過已有結果的組合，只查缺的 |
| 部分結果可用 | 已完成的部分照常顯示與排序，不因未完成而隱藏 |
| 明確標示 | UI 顯示「已完成 N／M」與未完成原因（配額用盡／軟封鎖／逾時） |
| 不以部分結果誤判 | 追蹤條件在 Partial 狀態下**仍可觸發達標通知**（已查到的價格是真實的），但 Stale 狀態不可 |

## 4. 合規約束（產品層要求，非實作細節）

| 約束 | 內容 | 來源 |
|---|---|---|
| 遵循 robots.txt | Skyscanner 明確 `Disallow: /transport/*`，**系統不得抓取該站**，僅可產生連結 | 研究筆記第 12 節實測 |
| Google Flights 路徑 | robots.txt 禁止 `/travel/flights/search`、`/s/`、`/booking`；系統使用的 `/travel/flights?tfs=` **未被禁止**。**robots.txt 允許 ≠ ToS 允許**，仍屬風險 | 同上 |
| 節流義務 | 序列執行、隨機間隔、速率上限、被擋即停 | 同上 |
| 不規避封鎖 | 偵測到封鎖時停止並等待，**不得**以更換 IP、代理輪替、偽造指紋等方式規避 | 產品決策 |
| 無個資與金流 | 不蒐集個人資料、不處理付款、不代訂票 | scope-decision |

## 5. 可觀測性與人工恢復

速率限制與軟封鎖會讓功能**靜默失效**——表現為連續逾時而非明確錯誤，
2026-09-22 就因此白打 16 次而不自知。因此：

| 需求 | 內容 |
|---|---|
| 用量可視 | UI 顯示滾動視窗內已用量與剩餘配額 |
| 封鎖可辨識 | 區分「明確封鎖頁」與「連續逾時（軟封鎖）」，兩者訊息不同 |
| 等待時間可知 | 配額用盡時顯示「約 N 分鐘後釋出」，而非只說「稍後再試」 |
| 資料新鮮度 | 每筆結果顯示查詢時間；超過 2 個重掃週期標示 Stale |
| 人工恢復 | 提供手動觸發重掃；提供解除速率守衛的選項（明確標示風險自負） |
| 限制數字的誠實標註 | 任何顯示給使用者的限制值，須標明是實測值或推估值 |

## 6. 降級行為

| 失效對象 | 降級行為 |
|---|---|
| Google Flights 抓取失效（改版／長期封鎖） | 切換至 SerpApi（若有 key）；無 key 則停止自動掃描，仍提供外部查價連結供人工比價 |
| Telegram 不可用 | 掃描與結果顯示不受影響，僅 UI 標示通知未送達 |
| 無任何可用資料源 | 分頁仍顯示歷史結果與外部連結，明確標示「自動查價暫停」 |
