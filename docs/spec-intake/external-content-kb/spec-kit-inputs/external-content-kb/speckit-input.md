# Spec Kit Input: 外部內容知識庫（YouTube／Podcast／文章）

**Status:** Accepted
**Source Product Spec:** ../../product-spec.md
**Source Scope Decision:** ../../scope-decision.md
**Spec Feature Slug:** external-content-kb
**Handoff Order:** 1

## Feature Summary

讓 PO 把有參考價值的 YouTube 影片、Podcast、文章的**全文**納入 AlphaVibe，存進一個獨立的外部內容庫，
之後在 claude.ai 的 AlphaVibe 專案（及本機 Claude Code）討論投資時，agent 能全文檢索並引用，
且每次引用都附「作者個人觀點，未經查證」標註。摘要或觀點歸納只有在 PO 明確同意後才入庫。

## Actors

- PO（Stander）：提供連結與逐字稿、確認摘要、查詢並引用內容。唯一使用者，內容僅供個人使用。
- Agent（claude.ai 連接器與本機 Claude Code，皆為非唯讀端）：代 PO 建檔、匯入、查詢，並提出摘要草稿。
- 唯讀端（如 Cline 的查詢）：只能查詢，不得有任何寫入能力。

## Problem and Goal

PO 看過的影片、Podcast、文章常有參考價值，卻只能憑記憶或重看。既有評論庫只適合短評，
且中文全文查詢需 ≥3 字，不適合存逐字稿。目標：全文可檢索、可引用、出處清楚、不經 PO 確認不寫入摘要，
並讓 PO 日常操作簡單（約三步）、盡量不耗 token（逐字稿不經模型輸出）。

## In Scope

- 獨立的外部內容庫，與評論庫、定錨文章庫、Substack 庫、美股庫分開。
- 三種來源：YouTube、Podcast、文章；每筆含全文與中繼資料。
- 主要進件流程：PO 貼連結給 agent → agent 先查是否已存在 → 沒有則在資料匣 `poc/data/inbox/` 建立中繼資料已填、內文空白的檔案並回報路徑 →
  PO 開檔貼入逐字稿並存檔 → PO 說「匯入」→ 系統讀檔入庫。
- 另一種進件方式：PO 用 Google AI Studio 產出含中繼資料區塊的完整檔案放進資料匣，再說「匯入」。
- claude.ai 直接收全文：僅作短文備援，須在工具說明標明耗輸出 token。
- 全文檢索（搜尋回傳命中片段）與取全文（可指定段落範圍）。
- 去重、更新全文、刪除單筆。
- 摘要與全文分開存放，摘要經 PO 明確同意才入庫。
- 查詢在台股與美股兩個連接器都提供（含唯讀端）；寫入類只在非唯讀端。
- 專案指示更新：討論投資時先搜尋外部內容庫、含三步使用說明與 AI Studio prompt 範本。

## Out of Scope

- 評論庫既有資料的刪除或遷移。
- 修改定錨文章庫、Substack 庫的任何資料表或程式。
- 任何未經 PO 確認的自動摘要寫入。
- 對外公開、分享或匯出功能。

### 後續（不在第一版）

- 自動抓 YouTube 字幕、Whisper 轉錄。
- 網頁上傳端點（手機或 claude.ai 免經模型輸出進件）。
- 手機經 iCloud 存檔。
- 跨庫統一搜尋（含定錨文章庫、Substack 庫）。
- Podcast／頻道自動追蹤。

## User Scenarios

1. **建檔並匯入**（驗收案例為 EP466，Podcast「股市隱者」第 466 集）：PO 貼來源連結（以 YouTube 影片為例）請 agent 建檔 → 庫內無該影片時，資料匣出現中繼資料已填好、內文空白的檔案，agent 回報路徑；
   PO 貼入逐字稿、存檔、說「匯入」→ 入庫、可用關鍵字查到、結果帶標註；agent 輸出中沒有出現整份逐字稿。
2. **AI Studio 完整檔案**：PO 把含中繼資料區塊的完整檔案放進資料匣並說「匯入」→ 同樣入庫。
3. **短文備援**：PO 在 claude.ai 貼連結＋短文＋中繼資料 → 同樣入庫，規則與場景 1 相同。
4. **重複連結**：同一影片以不同寫法連結（youtu.be 與 watch?v=，其一帶 si= 與 t=）再匯入 → 不新增第二筆，回報既有那筆並詢問是否取代全文；
   選擇取代後，已確認摘要仍在。
5. **建檔時已存在**：PO 貼庫內已有的影片連結請建檔 → 不建檔，告知既有那筆。
6. **摘要確認**：匯入後 agent 提出摘要草稿 → PO 同意前庫內無該摘要；同意後才存入並標「已確認」；拒絕或沉默則仍無摘要。
7. **2 字詞檢索**：搜尋「財測」之類 2 字詞，若全文含有，必須命中並回傳片段與來源資訊；台股與美股連接器都查得到。
8. **缺必填欄位／內文空白**：檔案缺「頻道／作者」→ 該檔不入庫並指出缺的欄位，同批其他合格檔照常入庫；PO 未貼內容就說「匯入」→ 該檔不入庫，指出「內文為空」。
9. **唯讀端**：以唯讀連接器查詢可成功；匯入、建檔、更新、刪除、確認摘要的功能必須不存在或被拒絕。
10. **刪除**：PO 說「刪掉那支影片」→ agent 先確認是哪一筆，PO 明確確認後才刪。
11. **討論時自動引用**：在已更新專案指示的 claude.ai AlphaVibe 專案中，PO 談到庫內有的主題，agent 先搜尋並引用，附來源與標註（以實測對話驗證）。
12. **分段取用**：PO 要求查某段內容 → agent 以搜尋片段定位，只取需要的段落範圍，不整份讀入。

## Functional Requirements

- FR-001 提供獨立的外部內容庫，儲存 YouTube、Podcast、文章三類來源的全文。
- FR-002 每筆必填：來源類型、連結、標題、頻道／作者、日期。資料匣檔案開頭須有含這五項的中繼資料區塊；缺任一項該檔不入庫並指出缺哪個欄位，不影響同批其他檔案；內文為空白的檔案不入庫並指出「內文為空」。
- FR-003 每筆在所有查詢輸出中必須附「作者個人觀點，未經查證」標註，不可由呼叫端省略；標註由系統加上，不要求寫在檔案裡。
- FR-004 PO 說「匯入」時，系統讀取資料匣中尚未處理的檔案並入庫，全文不經模型輸出；每個檔案各自處理（單檔全有或全無），逐檔回報「成功／重複／失敗與原因」；已處理的檔案不得被誤當新檔再次匯入。
- FR-005 claude.ai 直接收全文（短文備援）：接收連結、中繼資料與全文並入庫；工具說明須標明此路徑耗輸出 token。
- FR-006 兩種進件方式套用完全相同的必填檢查、去重與標註規則。
- FR-007 單一來源入庫為全有或全無：任何一步失敗，庫內不得留下該筆的部分內容。
- FR-008 全文檢索：2 字中文詞必須可查到；結果列出來源資訊與命中片段，不回整份全文。
- FR-009 取單筆時可指定段落範圍，未指定則回傳全文，一律附完整中繼資料與標註；亦可取得該筆「已確認摘要」。
- FR-010 去重：以來源身分判斷（YouTube 為平台＋影片 ID；Podcast 優先 RSS guid；追蹤碼、時間點等網址參數不影響身分；youtu.be、watch?v=、shorts、live、手機版視為同一影片）。重複時不新增，回報既有那筆並詢問是否用新內容取代全文；取代時保留既有已確認摘要；全文雜湊相同但來源不同只警告不擋。匯入時只讀檔案開頭中繼資料區塊判斷來源是否已存在，已存在者不處理全文。
- FR-011 摘要與全文分開存放；僅在 PO 明確同意後才以「已確認」狀態入庫；查詢時可區分「全文」與「已確認摘要」。已確認摘要可撤回與修改（僅非唯讀端），修改視同重新確認須 PO 同意。
- FR-012 任何入口都不得在 PO 未確認時寫入摘要；唯讀連接器不得有任何寫入工具。
- FR-013 更新全文（重新匯入同一來源並確認取代）與刪除單筆；刪除須 PO 明確確認，僅非唯讀端提供。
- FR-014 查詢工具在台股與美股兩個連接器都提供並納入唯讀端；匯入、建立待匯入檔案、更新、刪除、確認摘要只在非唯讀端；既有唯讀限制機制與相關測試須同步更新。
- FR-015 每筆必須有連結；無連結的檔案匯入時被擋下並指出缺連結。
- FR-016 專案指示須包含：建立匯入檔的說法與流程；討論投資時先搜尋外部內容庫；三步使用說明；AI Studio prompt 範本。agent 遵循度以實際對話驗證，不視為系統保證。
- FR-017 每次匯入完成，agent 回報結果時附「下一步」提示，並逐檔主動提出摘要草稿供 PO 確認（草稿不入庫）；多檔時逐檔提出、逐檔確認。
- FR-018 建立待匯入檔案：PO 提供連結（及 agent 取不到的中繼資料）後，系統先判斷來源是否已存在（規則同 FR-010）；已存在則告知既有那筆、不建檔；不存在則在資料匣建立檔案，中繼資料區塊已填妥、內文空白，並回報路徑。標題、頻道／作者、日期無法取得時由 agent 詢問 PO，不得猜測填入。由服務端工具實際建檔（claude.ai 本身不能建立 PO Mac 上的檔案）；唯讀端不提供此功能。
- FR-019 安全：系統只讀取資料匣內的檔案，不得讀取該資料夾以外的路徑。
- FR-020 稽核：入庫、更新、刪除、摘要確認都要有可追的紀錄（何時、哪一筆）。
- FR-021 資料：每筆含來源類型、連結、標題、頻道／作者、日期、全文、入庫時間、（可選）已確認摘要；另存全文雜湊用於提示同內容重複；無自動過期，刪除僅由 PO 明確指示。

## Failure Behavior

| 情境 | 預期行為 |
|---|---|
| 資料匣不存在或沒有待處理檔案 | 不入庫，回報「資料匣沒有待匯入檔案」 |
| 檔案不可讀或編碼錯誤 | 該檔不入庫，指出哪個檔案、哪種問題，其他檔照常 |
| 內文空白 | 該檔不入庫，指出「內文為空」 |
| 缺必填中繼資料或格式錯誤 | 該檔不入庫，列出缺的欄位 |
| 連結無法判斷平台或影片 ID | 該檔不入庫，說明原因 |
| 建檔時來源已存在 | 不建檔，告知既有那筆 |
| 建檔時 agent 取不到標題、頻道、日期 | 不猜測，詢問 PO 補齊後才建檔 |
| 建檔工具無法在資料匣寫入檔案 | 不建檔，回報原因（細節於規劃階段確認） |
| 重複來源 | 不新增，回報既有那筆並詢問是否取代全文 |
| 短文備援超過傳輸上限 | 不入庫、不留半筆，回報「內容過長」並建議改走資料匣 |
| 入庫中途失敗 | 單筆全有或全無、庫內無殘留；重送不得造成重複 |
| 已入庫的檔案又被留在資料匣 | 不得重複入庫，回報「已處理」 |
| 摘要未經確認就被要求入庫 | 拒絕，說明須 PO 明確同意 |
| 唯讀端呼叫寫入類功能 | 該功能不存在或被拒，明確拒絕訊息 |
| agent 討論時沒有主動搜尋 | 屬遵循度問題，PO 可直接要求「查外部內容庫」，必要時調整專案指示 |

## Success Criteria

- 首個實例逐字稿（Podcast「股市隱者」第 466 集，簡稱 EP466，由 PO 以 AI Studio 產出）完成「建檔→貼入→匯入→檢索→引用」，匯入過程 agent 的輸出不含逐字稿。
- 抽測 5 個 2 字中文詞（取自 EP466 內文），每個都能命中。
- 所有查詢輸出 100% 帶「作者個人觀點，未經查證」標註（以測試逐項斷言）。
- 3 種連結寫法重複匯入同一影片，庫內只有 1 筆。
- 未確認的摘要寫入次數為 0（測試覆蓋：資料匣進件、短文備援與唯讀端）。
- 既有定錨文章庫、Substack 庫、評論庫與台美連接器的既有測試全數維持通過。
- PO 實際用三步流程完成一次完整使用，不需要查文件。

## Constraints and Assumptions

- 必須獨立於既有四個資料庫（評論、定錨文章、Substack、美股）。
- 資料匣固定為 `poc/data/inbox/`，該路徑已被 `.gitignore` 排除，第三方逐字稿不進 git。
- 查詢介面沿用定錨文章查詢的使用方式；唯讀端以既有機制限制寫入。
- claude.ai 只能呼叫工具、不能讀寫 PO 本機檔案；claude.ai 單次工具呼叫大小上限尚未查到，只影響短文備援，須在規劃階段實測。
- 系統無法判斷逐字稿是否完整（例如 AI Studio 長文被截斷），PO 存檔後自行檢查結尾。
- 手機（iCloud）存檔不在第一版；macOS 隱私權限是否允許服務讀 iCloud 未驗證。
- agent 能否自動取得 YouTube 標題、頻道、日期未驗證；取不到時詢問 PO。建檔需在 Mac 上開檔貼入，手機不支援。
- 檔案開頭中繼資料格式為草稿，規劃階段可微調，須同步更新 AI Studio prompt 範本。
- 不依賴 Substack 抓取功能（其尚未完成）。
- 假設：內容僅供 PO 個人使用，系統不提供對外公開、分享或匯出；PO 自行用 Google AI Studio 產出逐字稿。
- 工具的名稱與參數屬技術設計，留待規劃階段。
- 規劃階段須確認：建檔工具只能在資料匣內建立檔案；唯讀端不提供建檔；「待填寫」狀態的呈現方式；建檔寫入失敗時的處理。
- 專案指示須由 PO 更新並貼進 claude.ai 專案；連接器沿用既有密鑰路徑保護。
- 資料匣檔案狀態：待填寫（建檔後內文空白）→ 待處理（由系統在匯入時依內文是否為空判斷）→ 已處理（入庫成功，或 PO 對重複選擇放棄）；失敗者與「重複且 PO 尚未決定」者維持待處理。

- 去重、摘要確認、連接器範圍、更新與刪除：Q-003、Q-005、Q-009、Q-013。
- 必填欄位、無連結來源、使用流程與 prompt 取得方式：Q-006、Q-004、Q-020、Q-021。
- 驗收案例 EP466：Q-007。
- 非阻擋但採建議做法、留規劃細化：Q-010（Podcast 身分）、Q-016（同內容不同來源只警告）、Q-017（摘要撤回／修改）；Q-018（claude.ai 上限實測）。
- 完整決策紀錄：`../../clarification-log.md`。
