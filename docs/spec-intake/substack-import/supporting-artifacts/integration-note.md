## 2. 產品層面的請求行為要求

| 項目 | 要求（來源） | 具體數值 |
|------|--------------|----------|
| 請求量 | 每作者每次執行至多 1 次 feed 請求（SRC-003 建議每日 1～2 次） | 排程 1 次／日；即時取得受最小間隔限制；**任何輪詢（排程或即時）都計入同作者最小間隔**，排程落在間隔內則跳過並記錄、不算失敗（Q-121） |
| 逾時 | 必須設定逾時，逾時視為該作者本次失敗（SRC-001 Function） | 數值待規格階段（Open，非阻擋） |
| 條件請求 | 每次帶上次的 ETag；304 視為「無變化」，不解析、不寫庫（SRC-003 §3） | — |
| 識別 | 通用 User-Agent，不含 PO email 或個資；不帶 cookie、不登入（SRC-001） | — |
| 作者間隔 | 多位作者之間須有間隔，避免短時間連續請求（SRC-001 低頻與禮貌；SRC-003 §6） | 數值待規格階段 |
| robots.txt | 遵守；每次執行前以快取方式確認，不逐次重抓（推論） | — |
| 403／429 退避 | 該作者本次停止、不重試、告警；下次排程才再試；同一作者連續被擋的處置（是否暫停該作者）待 PO（Q-102 相關） | 不得即時重試 |
| 非預期內容 | 回應非預期格式（例如 HTML 挑戰頁）視同被擋，不寫庫 | — |

## 3. 失敗行為（摘要，完整見 error-handling-matrix.md）

- 任何失敗都不得寫入半成品；已存文章不被覆寫。
- 單一作者失敗不影響其他作者。
- 失敗訊息不含標題與回應內文；日誌僅記作者代號、HTTP 狀態、時間。
- 被擋時 Telegram 通知固定文字，不含標題。

## 4. 流程（順序）

排程或即時取得 → 取得 011 鎖（失敗：回報忙碌）→ 讀設定檔取得啟用作者 → 逐作者：（即時取得先檢查最小間隔）→ 條件請求 feed → 304：結束該作者 → 200：解析條目 → 以 guid／URL 去重 → 首次執行套用 14 天窗 → 判斷免費／僅預覽 → 寫入 `substack.db`（文章寫入同一交易）→ 下載圖片（即時取得與排程皆同步下載；失敗僅記缺圖，缺圖由排程補下載）→ 彙整新增清單 → 釋放鎖 → 發 Telegram 通知（含作者＋標題）→ 日誌（不含標題）→ 回報空間現況。

## 5. 資料對應

| RSS 欄位 | 儲存意義 |
|----------|----------|
| guid（isPermaLink=false） | 去重鍵之一 |
| link | 去重鍵之二／來源連結（乾淨 `/p/<slug>` 永久連結） |
| title | 文章標題（只存庫與通知，不入日誌） |
| pubDate | 發布時間（首次 14 天窗判斷依此） |
| description | 預覽摘要 |
| content:encoded | 全文（免費）或預覽內文（付費） |
| enclosure | 封面圖（是否下載見 Q-114） |
