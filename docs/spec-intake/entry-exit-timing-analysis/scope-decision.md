# Scope Decision: 進出場時機分析工具

**Feature Slug:** entry-exit-timing-analysis
**Last Updated:** 2026-09-01

## MVP In Scope

全部 6 項功能於 Q-001~Q-006（clarification-log.md）確認納入：

- 進場後損益追蹤（FIFO 成本法，已實現＋未實現損益皆含）
- 現價相對歷史價格區間的高低位判斷（股價本身，非既有的 PER 百分位）
- 停損/停利觸發判斷——門檻由 PO 與 Claude **逐檔討論後設定**（協作式，
  非固定公式、非全自動、非 PO 單方決定）
- 基本面訊號與價格走勢的背離偵測
- 既有營收年增率轉強/轉弱判斷範圍擴大
- 觸發訊號時（停損/停利/背離）一併建議該檔持股接下來可以怎麼調整
  （換股/減碼/對沖/續抱理由），範圍鎖定在觸發當下的該檔持股

**呈現形式**：MCP 工具＋報告頁面整合，兩者都要（Q-004）。
**主動性**：整合進既有模組D每日排程（17:00 自動跑），主動觸發提醒並
寫入 Layer 2 立場記錄（Q-005）。

## Out Of Scope

- 自動下單／自動執行交易
- 老芋頭訊號的自動化解讀（維持既有邊界：純陳述真人導師的交易事實，
  不做基本面判斷）
- 新增外部資料源或第三方 API
- **更廣的主動策略/選股發現**（Q-006 已排除）——例如整合
  `screen_stocks`／`market_scan` 主動比對「有沒有更好的候選標的」；
  FR-E06（product-spec.md 正式編號，對應 extracted-requirements.md 的
  FR-cand-06）的策略建議僅限「觸發訊號當下、該檔持股怎麼辦」，不是
  主動掃描市場找新機會

## Deferred Or Later

- （本輪 Q-001~Q-006 確認後，原本列為 Deferred 的「背離偵測」「營收趨勢
  範圍擴大」已改列 MVP In Scope，此節目前無項目）
- 若未來要做「更廣的主動策略發現」（見 Out of Scope），屬於獨立的新
  功能範圍，建議另開一輪 pre-spec，不在本功能範圍內擴充

## Split Feature Decisions

PO 2026-09-01 同意分兩階段交付：

| Spec Feature Slug | Scope Summary | Dependencies | Handoff Order | Status |
|-------------------|---------------|--------------|---------------|--------|
| entry-exit-foundation | **階段A（基礎）**：FR-E01 損益追蹤（FIFO，已實現＋未實現）、FR-E02 股價歷史高低位判斷、FR-E07 的 MCP 工具部分 | 既有 `get_trade_ledger`／`get_stock_price_history`／`get_holdings`／`_downside_risk` 邏輯框架 | 1 | Draft |
| entry-exit-signals | **階段B（進階）**：FR-E03 討論式停損停利門檻設定與觸發、FR-E04 背離偵測、FR-E05 營收趨勢判斷範圍擴大、FR-E06 觸發時策略建議、FR-E07 的報告頁面整合部分、FR-E08 每日排程整合 | 階段A（需要 FIFO 損益與歷史百分位作為判斷基礎）；既有模組D排程與 Layer 2 立場記錄寫入路徑 | 2 | Draft |

拆分理由：階段A 風險低、可獨立驗證，完成後 PO 即可在對話中實際使用
（解決本次事故的核心痛點——手動拼湊損益與價位判斷）；階段B 的訊號
判斷與主動提醒都建立在階段A 的計算基礎上，分開交付可讓價值提早兌現，
也避免一次吞下 4 份必要技術文件（API／資料模型／狀態流程／告警）的
交付風險。
