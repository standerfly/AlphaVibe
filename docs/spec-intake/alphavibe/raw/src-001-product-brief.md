## 1. 功能概述 (Feature Overview)

AlphaVibe 是一個台股為主、兼顧美股的投資資訊儀表板，專為個人投資者設計。初期供個人使用，未來擴展至少量受信任的朋友群，以 Docker 容器化方式部署於雲端。

**痛點：** 投資資訊分散在 LINE 群組、各投資網站與 Facebook 社群，每天需要手動彙整才能形成完整的市場觀點，耗時且容易遺漏。

**解法：** AlphaVibe 在每個交易日收盤後，收集並彙整分散的訊息來源，產出結構化的總結報告（含來源連結），並由 AI Agent 提出市場觀點與買賣訊號，協助投資者高效完成當日覆盤，為下一個交易日做好準備。

**核心功能面向：** 收集 → 彙整 → 分析 → 建議（市場觀點 + 買賣訊號）

**AI 知識庫特色：** 長期累積三個獨立投資哲學模組，建立三層知識庫供 AI Agent 參照。架構以穩定為優先，各模組保持邏輯獨立，避免分析視角互相稀釋：

**Layer 1 — 哲學庫（Philosophy Library，慢變）**
採用模組化檔案載入機制。系統在啟動時，自動讀取指定配置目錄下的所有 `.md` 檔案內容，並將其拼接至 AI Agent 的 System Prompt 中：
- **Module A：于志宇哲學**：低本益比（PER ≤ 12）、高殖利率（≥ 7~9%）、領導人眼光、恐慌分批買入、非共識早期訊號
- **Module B：股癌筆記**：需求/成本驅動分析、產業排擠效應、邏輯推演
- **Module C：定錨報告**：結構化財務指標、產業趨勢量化預估、regex 可解析格式

**Layer 2 — 個股立場（每週更新）**
SQLite 結構化表格，LLM 批次排程抽取後人工修正，查詢為純 SQL：
`{ code, name, stance, reason, date, entry_condition, valuation_metric, time_horizon, risk_factor, source_ref }`

**Layer 3 — 每日評論（每日 ingestion）**
SQLite FTS5 全文搜索，本地無外部依賴；未來語意需求強時再升級為本地 embedding

**資料來源與輸入：**
- **手動貼入：** LINE 訊息、定錨 Email、股癌 FB 貼文。
- **外部 API：** 整合 FinMind (台股財報/數據) 與 Alpha Vantage (美股/全球數據)。
- **按需觸發：** 使用者提供 URL 觸發特定媒體網頁爬取。
- **視覺解析：** 導入 Vision LLM (如 Claude Vision) 處理市場圖表或截圖。
- **URL 文章內容：** 非同步抓取，抓不到只存連結，不阻塞主流程。

**資料來源（混合收集模式）：**
- 結構化市場數據（自動）：FinMind API（台股）、Alpha Vantage（美股），收盤後排程抓取
- LINE 群主發言（手動貼入 → 未來 n8n）
- Facebook 文章（手動貼入，存入資料庫）
- 財經媒體文章（user-triggered：系統列出連結，使用者確認後爬取；或手動貼入）
- 圖片文章（Claude Vision API 處理截圖、掃描圖）
- 自選股與持股清單（使用者手動維護）

**輸出介面：** 單頁式儀表板，報告內容可連結回原始來源；未來規劃自動通知功能。

**即時性：** 不要求即時，以每日收盤後的全面檢視為主要使用情境，速度以排程機制補足。

**持倉檢視：** 預留為未來功能，v1 不在範圍內。

## 2. 業務背景與優先級 (Business Context & Priority)

> 為什麼現在要做？這個功能對業務/使用者的影響是什麼？優先級如何？預計上線時間？

- **優先級 (Priority):** P0 (核心工具)
- **目標上線時間 (Target Launch):** 盡快完成 MVP 版本
- **業務動機 (Business Motivation):**
  目前投資資訊極其分散（LINE, Email, FB, 財經網），每日手動彙整耗時且容易遺漏關鍵訊息。建立 AlphaVibe 可將「資訊收集 $\rightarrow$ 結構化分析 $\rightarrow$ 策略建議」流程自動化，將每日覆盤時間從 1 小時縮減至 10 分鐘內，並透過 AI 知識庫確保分析視角的一致性。

## 4. MVP 範圍 (MVP Scope)

### 4a. 本次要做 (In Scope)
- 手動貼入三來源資料（LINE 群組、LINE 一對一、定錨 email、股癌 Facebook）
- AI 知識庫三層建立：Layer 1 投資哲學、Layer 2 個股立場、Layer 3 每日評論
- 外部數據整合：FinMind (台股) 與 Alpha Vantage (美股) API 基礎整合
- 內容抓取與解析：支援使用者觸發的單一網頁爬取、Vision LLM 圖片解析
- 每日收盤後產出結構化報告（市場方向 + 明日策略 + 個股更新）
- 自選股（watchlist）：新增、刪除、檢視，欄位 {code, name, added_date, memo}
- 儀表板：單頁式，自選股以可收合面板呈現於右側/底部

### 4b. 本次不做 (Out of Scope)
- 持倉追蹤（成本價、損益、部位大小）
- 自動爬取或 n8n 自動化
- LINE 聊天中 [照片] 的自動解析（v1 跳過，記錄佔位符）
- 自動通知推播
- 多用戶管理（僅支援小規模朋友群，不含完整權限管理系統）

### 4c. 未來再考慮 (Deferred)
- n8n 自動化資料收集
- 持倉管理與損益追蹤
- 自動通知（LINE / email）
- Feedback Loop：使用者修正 AI 結論回寫優化 Layer 1 模組（設計細節見 Q4）
- 擴展至更大規模的多用戶支援

## 5. 功能需求草稿 (Functional Requirements Draft)

> 描述系統「應該做什麼」，不要寫實作細節。每條需求應可測試。

- FR-001: 使用者可手動貼入來自 LINE、定錨、股癌的原始文字，系統依來源 tag 儲存
- FR-002: 系統可從定錨 email 文字以結構化解析（非 LLM）抽取個股代碼、EPS 財測、定錨觀點
- FR-003: 系統可透過 LLM 從 LINE 訊息抽取群主的個股立場，產出 {code, name, stance, date} 供人工確認
- FR-004: 每日收盤後，系統採取「分段摘要 $\rightarrow$ 最終整合」流程產出報告：
  - 階段一：將 Layer 3 原始訊息按個股/主題進行初步摘要，過濾雜訊。
  - 階段二：結合初步摘要、Layer 1 哲學、Layer 2 立場及外部 API 數據，產出最終報告（含市場方向、明日策略、個股更新）。
- FR-005: 使用者可在儀表板新增、刪除、檢視自選股（{code, name, added_date, memo}）
- FR-006: 自選股有新消息時，在報告中優先顯示於第一區；其他今日提及股票顯示於第二區
- FR-007: 報告內容可連結回原始來源片段
- FR-008: 系統可透過 FinMind (台股) 與 Alpha Vantage (美股) API 獲取指定個股的基礎財務數據與價格走勢
- FR-009: 使用者可提供 URL，系統觸發爬蟲抓取網頁內容並交由 LLM 分析
- FR-010: 使用者可上傳圖片，系統透過 Vision LLM (如 Claude Vision) 解析圖表關鍵資訊並納入每日報告
- FR-011: 系統於每日收盤後排程抓取自選股最新收盤價，若觸及 Layer 2 定定義的 `entry_condition`，在當日報告中標記「觸發買入條件」提醒
- FR-013: 當 Layer 3 當日訊息涉及某個股，且與 Layer 2 已定調的立場明顯矛盾時，系統在報告中標記「⚠️ 立場衝突」並列出衝突摘要，不自動更新 Layer 2，由使用者決定是否修正
- FR-012: 系統實作「前置清洗層 (Preprocessing Layer)」，解析 LINE 匯出文字時依下列規則處理後再存入 Layer 3（FTS5）：
  - 雜訊過濾：使用 Regex 移除冗餘時間戳、重複的系統通知及無意義的格式符號。
  - 內容過濾：`[照片]` / `[影片]` / `[貼圖]` / `[相簿]` / `[檔案]` $\rightarrow$ 跳過，v1 不處理。
  - 狀態過濾：`已收回訊息` $\rightarrow$ 跳過，不儲存被撤回的內容。
  - 正常存入：清洗後的乾淨文字訊息 $\rightarrow$ 正常存入，附帶 `{sender, timestamp, raw_text, source_tag}`。
- FR-014: 系統應支援投資哲學模組的擴展。使用者透過在指定配置目錄新增 `.md` 檔案即可增加分析視角；新模組於系統重啟後生效。

## 6. 使用情境 (User Scenarios)

**場景 1 — 正常流程 (Happy Path):**
1. **資料輸入：** 使用者在收盤後，將今日 LINE 群組、定錨 Email、股癌 FB 的文字內容貼入系統 $\rightarrow$ 上傳今日關注的市場分析截圖 $\rightarrow$ 提供 2-3 個關鍵財經網頁 URL 觸發爬取。
2. **自動處理：** 系統同步呼叫 FinMind/Alpha Vantage API 獲取最新財務數據與價格 $\rightarrow$ Vision LLM 非同步解析截圖內容 $\rightarrow$ LLM 先對 Layer 3 原始資料進行分段摘要 $\rightarrow$ 最終結合 Layer 1-3 知識庫產出市場觀點與報告。
3. **報告生成：** 系統整合上述所有異質資訊，產出結構化報告，路徑為：「市場總體方向 $\rightarrow$ 明日操作策略 $\rightarrow$ 自選股重點更新」。
4. **檢視與決策：** 使用者在儀表板查看報告，針對有疑問的結論點擊連結回溯原始來源片段，最終完成明日交易計畫。

**場景 2 — 例外流程 (Exception Path):**
1. **API 請求失敗：** 當 FinMind 或 Alpha Vantage API 回傳錯誤或達到限額時，系統應記錄錯誤並在報告中標記「數據更新失敗」，使用最後一次快取數據，而非中斷整個報告生成流程。
2. **Vision 解析錯誤：** LLM 無法正確辨識圖片中的圖表數據時，系統應在報告中標記「圖片解析不確定」，並保留原圖連結供使用者人工核對。
3. **資料抽取格式錯誤：** 當 LLM 抽取個股立場格式不符（例如缺少代碼）時，系統將該片段移至「待人工確認」區塊，不直接寫入 Layer 2 結構化表格。

## 7. 成功標準 (Success Criteria)

- **功能完整度：** 實現從手動貼入資料到產出結構化報告的完整閉環。
- **分析準確度：** 經人工抽樣核對，個股立場抽取與市場方向總結的準確率 $\ge 90\%$。
- **效率提升：** 使用者每日覆盤所需的手動彙整時間顯著降低。
- **系統穩定性：** 每日收盤後的排程任務能穩定執行，無毀滅性崩潰。

## 8. 限制條件與假設 (Constraints & Assumptions)

### 系統設計原則
- **穩定優於速度：** 系統以準確性與穩定性為第一優先，速度透過排程機制補足，不追求即時性。
- **最小化 LLM 請求：** 盡量減少對 AI Agent 的 API 呼叫次數，降低成本與錯誤率。但為了確保長文本處理的穩定性，允許在報告生成時採取「分段摘要 $\rightarrow$ 最終整合」的兩階段呼叫。
- **前後端分離：** 系統維持前後端分離架構，介面與邏輯層獨立部署。
- **功能最小化：** 功能以最小可用為原則，每個模組獨立開發與測試後再整合，方便 AI 輔助開發與日後維護。
- **架構文件優先：** 系統架構與模組間溝通文件需完整維護，參數命名保持全系統一致性。

### 部署假設
- 以 Docker 容器化方式部署於雲端。
- Layer 1 模組目錄建議透過 Docker Volume 掛載，以實現無需重新構建鏡像即可更新哲學庫。
- 初期單人使用，未來擴展至少量朋友（小規模多用戶）。

## 9. 錯誤處理 (Error Handling)

| 失敗情境 (Failure Case) | 預期行為 (Expected Behavior) | 復原方式 (Recovery) |
|---|---|---|
| 外部 API (FinMind/AV) 宕機 | 報告中標記數據缺失，不阻塞報告生成 | 使用快取數據 / 手動觸發重新抓取 |
| LLM API 額度耗盡 / 逾時 | 記錄錯誤日誌，通知使用者 | 切換備用模型 (Fallback LLM) / 手動重新執行 |
| 爬蟲被目標網站封鎖 | 記錄 URL 並標記為「抓取失敗」 | 建議使用者手動貼入內容 |
| SQLite 資料庫鎖定 | 實作簡單的重試機制 (Retry logic) | 自動重試 3 次後記錄錯誤 |
